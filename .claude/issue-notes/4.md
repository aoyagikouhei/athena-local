### 変更内容と根拠

**1. `Store::new(retention: Duration)` と `Inner.retention: f64`（判断 9）**

- `Store` と `Inner` の `Default` derive を外す（`src/store.rs:13,18`）。残すと `retention` に 0.0 が入り「即座に全部捨てる」経路ができる。ミューテーション候補にも入れる。
- 内部表現を `f64`（秒）にするのは比較相手の `completed_at` が f64 の UNIX 秒だから（`:41`、`now()` は `:242-247`）。変換は `Store::new` の 1 箇所（`as_secs_f64()`）。
- 公開シグネチャは `Duration`（判断 10 の `Config.retention: Duration` に合わせる）。

**2. トークン対応表の掃除（判断 5）**: `Execution` にフィールドは足さない。`executions.retain` のあとに `tokens.retain(|_, claim| executions.contains_key(&claim.id))` で、実行が消えた `Claim` を消す。計算量は `Execution.token` を持つ案と同じ桁（`tokens` と `executions` は 1:1）で、`Store::get` の clone が増えず、`submit` も変えない。

**3. `Inner::sweep(now: f64)`（判断 4・7・8）**

```rust
/// 期限切れの終端状態の実行と、その ClientRequestToken を捨てる。
/// completed_at が None（QUEUED / RUNNING）は捨てない。テストからは時刻を渡して直接呼ぶ。
fn sweep(&mut self, now: f64) {
    let retention = self.retention;
    self.executions
        .retain(|_, execution| execution.completed_at.is_none_or(|completed_at| now - completed_at < retention));
    let executions = &self.executions;
    self.tokens.retain(|_, claim| executions.contains_key(&claim.id));
}
```

判定は `completed_at` だけを見て `state` は見ない。`completed_at` が入るのは終端の 2 経路（`:189`、`:215`）だけなので「終端状態のものだけ」と同値。

**4. `lock()` が掃除まで済ませる（判断 4）**

```rust
/// ロックを取り、続けて期限切れを捨てる。公開メソッドはすべてここを通る。
fn lock(&self) -> std::sync::MutexGuard<'_, Inner> {
    let mut inner = self.inner.lock().expect("store poisoned");
    inner.sweep(now());
    inner
}
```

既存の `lock()`（`:220-222`）を公開メソッド 5 本すべてが通るので、呼び出しを散らさず掛け忘れも起きない。掃除が `submit` の照合より先に走るので、期限切れトークンの再送は自動的に「未登録」＝新しい実行になる（分岐を書かない）。「前回の掃除から一定時間未満ならスキップ」は入れない（起きていない性能問題への最適化）。

**5. `parse_retention`（フェーズ 2、判断 3）**: `parse_results`（`:100-145`）と同じく環境変数リーダを引数で注入し、`from_env` から `parse_retention(optional_env)?` で呼ぶ。`Result<Duration, String>`。

```rust
fn parse_retention(env: impl Fn(&str) -> Option<String>) -> Result<Duration, String> {
    let Some(text) = env("ATHENA_LOCAL_RETENTION_SECONDS") else {
        return Ok(DEFAULT_RETENTION);
    };
    let seconds: u64 = text.parse().map_err(|_| {
        format!("ATHENA_LOCAL_RETENTION_SECONDS: 1 以上の整数（秒）を指定してください: {text:?}")
    })?;
    if seconds == 0 {
        return Err("ATHENA_LOCAL_RETENTION_SECONDS: 0 は指定できません（無期限にしたいなら大きな値を入れてください）".to_string());
    }
    Ok(Duration::from_secs(seconds))
}
```

## マージ後の周知事項

- 終端状態の実行情報と `ClientRequestToken` の対応は、完了から `ATHENA_LOCAL_RETENTION_SECONDS`（既定 3600 秒）で消える。捨てた後の GetQueryExecution / GetQueryResults / StopQueryExecution は `QUERY_EXECUTION_NOT_FOUND`。StopQueryExecution は終わったクエリへの 200 が期限後は 400 になる。
- 期限後の同じトークンの再送は新しいクエリになる（INSERT / CTAS はもう一度走る）。期限を短くすると冪等性の窓も縮む。
- 期限は完了から数え、読んでも延びない。期限より長く GetQueryResults をページングすると残りを失う。
- 読めない値と 0 は起動時に止まる。無期限にしたいなら大きな値を入れる。
- 本物の Athena の保持期間・期限切れ ID のエラー・期限切れトークンの扱い・期限切れ ID への Stop は未実測（README の Caveats）。
