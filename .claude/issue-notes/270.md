# #270 S3 Tables の Context の LOCATION 無し・非 EXTERNAL の CREATE TABLE で #266 が測っていない形を本物で測る

## 出どころ

- issue #270。#266 の先行実測（ROUND=13・14、生データ `$HOME/athena-unquoted-ddl-measurements/run-20260926-221348`・
  `run-20260926-223637`）の「範囲外の発見」の 1（`.claude/issue-notes/266.md` の「範囲外の発見」1）が根拠。
  S3 Tables の Context で LOCATION の無い、非 EXTERNAL の CREATE TABLE の ROW FORMAT・PARTITIONED BY・
  CLUSTERED BY・TBLPROPERTIES は、開始して（StartQueryExecution は成功）FAILED になり、結果ファイル本体・
  `.metadata` とも置かれない（vc4・w7・z6〜z17）。athena-local は今は Trino の構文チェックに任せていて、
  開始時の構文エラー（MALFORMED_QUERY）になってしまう
- issue #270 本文の「測っていない形」1〜3（句どうしの優先順、Iceberg の書き方の `PARTITIONED BY`、Iceberg で
  有効な `TBLPROPERTIES`）と、周辺の名前の形（z15〜z17 は 1 部の名前だけ測った）を本物で測るのが目的
- 同じ族の判定がすでにある: `src/operation/unquoted_ddl/create_table/hive.rs` の `read`（Hive の句を順に読む）と
  `s3_tables_stored_as`。句ごとに文言と ErrorType を選ぶ形に広げれば済む見込みで、**#266 の実装と一緒に扱ってよい**
  （#266 の issue 本文にも同じ記載がある）

## 実測の手順

- スクリプトのパス: `tools/measure/unquoted-ddl.sh`（`ROUND=16` を追加。ROUND=1〜14 の挙動は変えていない。
  ROUND=15 は issue #251 が別ブランチ `main-measure-251` で使うため、このブランチには無い。13・14 の次は 16）
- 実行コマンド:
  ```
  tools/dev.sh OUTPUT=s3://your-bucket/prefix/ DB=your_db ROUND=16 \
    S3TABLES_CATALOG=s3tablescatalog/your-bucket S3TABLES_NS=your_ns \
    bash tools/measure/unquoted-ddl.sh
  ```
- 必須の環境変数: `OUTPUT`・`DB`
- 任意の環境変数:
  - `S3TABLES_CATALOG`・`S3TABLES_NS`（無ければ cl・pr・pn・pa・tp 群の全項目（31 項目）が
    「未測定（S3TABLES_* 未設定）」で残る。このラウンドは全項目が S3 Tables の Context だけを使う）
  - ほかは既存と同じ `CATALOG`・`REGION`・`OUT_DIR`・`POLL_TIMEOUT`・`RETRY_MAX`・`RETRY_DELAY`
  - `FEDERATED_CATALOG`・`CREATE_GLUE_CATALOG`（GLUE のデータカタログ）はこのラウンドでは使わない
- 出力先: `${DEV_HOST_HOME:-$HOME}/athena-unquoted-ddl-measurements/run-<日時>/`
- 本物への呼び出し回数の見込み（StartQueryExecution）: 33（S3TABLES_* あり）／2（無し）。preflight 2 +
  常に投げる cl 群 2・pr 群 10・pn 群 6・pa 群 6・tp 群 7（計 31）。受理された CREATE TABLE ごとに、その場で
  SHOW CREATE TABLE 1 本・DROP する後始末 1 本が増える（それぞれ最大 +31。cl0 は受理される見込み（対照）、
  cl1 は z15 の再現で FAILED になる見込み。ほかの項目が受理されるかどうかは、このラウンドで確かめるのが目的）
- DDL・課金: cl・pr・pn・pa・tp 群の CREATE TABLE はすべて 0 行で、S3 Tables の Context（作る Context と
  消す Context は常に同じ）だけに投げる。LOCATION は付けない（このラウンドは全部 LOCATION 無し）。受理された
  ら DROP の前に同じ Context で `SHOW CREATE TABLE <名前>` を投げて結果ファイル本体を取得し
  （`run_create_then_drop_ctx_showcreate`。SHOW CREATE TABLE が失敗しても DROP は続ける）、そのあと
  DROP TABLE IF EXISTS で消す（trap でも保険をかける）。スキャンは無く最小課金の見込み。FAILED になった項目の
  結果ファイル取得・SHOW CREATE TABLE の結果ファイル取得（`aws s3 cp`）は S3 の読み取りで Athena のクエリ
  課金には乗らない

## 項目 ID の一覧

各項目が issue 本文のどの番号（1〜3）を確かめるかをまとめる。すべて Context
`Catalog=<S3TABLES_CATALOG>,Database=<S3TABLES_NS>`（`<S3>`）に投げ、LOCATION は付けない。SERDE は
`'org.apache.hadoop.hive.serde2.OpenCSVSerde'`。受理されうるので全項目を `run_create_then_drop_ctx_showcreate`
（受理されたら SHOW CREATE TABLE を挟んでから同じ Context で DROP）で投げる。

### cl 群（対照）

| ID | SQL の形 | 何を確かめるか |

| cl1 | `(n int) PARTITIONED BY (p int)` | z15（Hive の型付きの `PARTITIONED BY`）の再現。FAILED になる見込み |

| pr5 | CLUSTERED BY + TBLPROPERTIES |
| pr6 | PARTITIONED BY + STORED AS PARQUET |
| pr7 | CLUSTERED BY + STORED AS PARQUET |
| pr8 | ROW FORMAT SERDE + TBLPROPERTIES（`table_type`='ICEBERG'） |
| pr9 | PARTITIONED BY + CLUSTERED BY + ROW FORMAT SERDE + STORED AS PARQUET + TBLPROPERTIES（全部） |
| pr10 | COMMENT + PARTITIONED BY |

w7（STORED AS + ROW FORMAT → ROW FORMAT の文言）は測ってあるが、ROW FORMAT と PARTITIONED BY・CLUSTERED BY・

- SHOW CREATE TABLE（受理された 8 件）: どれも `CREATE TABLE <ns>.<t> (..)` に `TBLPROPERTIES ('table_type'='iceberg', 'write_compression'='zstd')`
  が付く（tp2 は `'format'='parquet'` も）。指定しなくても `write_compression`='zstd' が入る

判定への効き目（`hive.rs` の `read` と `s3_tables_stored_as` の族を広げるとき）:

- 開始して FAILED になる句の優先順は **CLUSTERED BY > ROW FORMAT > STORED AS > PARTITIONED BY（Hive の型付きの形）> 未知の TBLPROPERTIES**。
  対ごとに測ったもの: CLUSTERED と ROW FORMAT（pr3）・STORED AS（pr7）・PARTITIONED（pr2）・TBLPROPERTIES（pr5）、ROW FORMAT と
  PARTITIONED（pr1）・STORED AS（w7）・TBLPROPERTIES（z10・pr8）、STORED AS と PARTITIONED（pr6）・TBLPROPERTIES（w8）、PARTITIONED と
  TBLPROPERTIES（pr4）。矛盾する対は無かった
- 名前の形（2 部・`AwsDataCatalog` の 3 部・IF NOT EXISTS・バッククォート・列リスト無し）では文言は変わらない。例外は列リスト無しで
  CLUSTERED BY・ROW FORMAT・STORED AS のどれも無いとき（pn6）で、`At least one column is required ...`（2 / 1006）が未知の TBLPROPERTIES より先
- PARTITIONED BY は、括弧の中に型があれば（Hive の形。列リストにある名前でも）Invalid PARTITIONED BY。型の無い列名・変換
  （`bucket`・`day`）は Iceberg の形として受理。型の無い形の後ろに ROW FORMAT が続くと、開始時に Trino 形の構文エラーになる（pa6）。
  型の無い形で列リストに無い名前は開始して FAILED、2 / 1100
- TBLPROPERTIES は、Iceberg の有効なキーは受理（キーの大文字小文字によらない）、未知のキーが 1 つでもあれば FAILED、`'table_type'='HIVE'`
  は開始時に弾く
