# #279 無引用の awsdatacatalog. の置換（#260）で測っていない Context・文・名前の形を本物で測る

## 出どころ

- issue #279。#260（無引用の `awsdatacatalog.` の置換を、本物が実行したと測った Context と文の組に
  広げた。判定の表は `src/operation/unquoted_alias.rs` の `by_context`、名前の形は `src/catalog.rs` の
  `is_unquoted_aws_data_catalog`）で測れなかった形と、測っていない Context・文の組が根拠
- #260 の実測は `tools/measure/unquoted-ddl.sh` の ROUND=12（2026-09-27、生データ
  `$HOME/athena-unquoted-ddl-measurements/run-20260926-210106`。ノートは `.claude/issue-notes/260.md`、
  結果表は `docs/dev/measurements/statements.md` の「無引用の awsdatacatalog. の置換の周辺」の節）
- #260 の o 群（このラウンドが引き継ぐ定義）:
  - 実在する表 `<DB>.<PROBE>_o`（`n`・`s` の 1 行）を CTAS で作り、全項目で使い回して最後に消した
  - o0: S3 Tables の Context の `SELECT 1`（対照）。o1: 同 Context の
    `SELECT * FROM awsdatacatalog.<DB>.<t>`。o2: 同 Context の `INSERT INTO awsdatacatalog.<DB>.<t>
    VALUES (2, 'y')`。o5: 実在しないカタログ `nosuchcatalog260` の Context の同じ INSERT。o6・o7: 既定の
    Context で `awsdatacatalog."<DB>".<t>`・`awsdatacatalog.<DB>."<t>"`（引用符付きの部品を 1 つ）。
    o8: 既定の Context で `SELECT awsdatacatalog.<DB>.<t>.n FROM awsdatacatalog.<DB>.<t>`（4 部の列の
    参照）。o10・o11: Context の Catalog を省略（`Database=<DB>` だけ）で `awsdatacatalog.`・
    `AWSDATACATALOG.`
  - o3・o4（連携カタログの Context の SELECT・INSERT）・o9（AwsDataCatalog 以外の別名キーを無引用の
    大文字混じりで書いた形）は、#260 のアカウントに連携カタログが無く未測定のまま残った
  - すべて SUCCEEDED、Query は送った文のまま（`awsdatacatalog.` は落ちない）。返った
    `QueryExecutionContext` の Catalog は o6〜o8 で小文字の `awsdatacatalog` になった（#157 と同じ）
- #260 の残り（このラウンドで測る、issue #279 本文の 1〜6）:
  1. 連携カタログの Context の SELECT・INSERT（o3・o4 の再現）と、`AwsDataCatalog` 以外の別名キーを
     無引用の大文字混じりで書いた形（o9 の再現）。#266 で `CREATE_GLUE_CATALOG=1` により自分の
     アカウントの Glue を指す GLUE 型のデータカタログを一時的に作って測れたので、同じ方法で測れる見込み
  2. 既定の Context で、測った 5 種（SELECT・INSERT・CTAS・CREATE VIEW・EXPLAIN）以外の文
     （DELETE・UPDATE・MERGE・DROP VIEW・SHOW CREATE VIEW・`ALTER TABLE ... RENAME TO ...` の 2 つ目の
     名前・SHOW COLUMNS/TBLPROPERTIES/PARTITIONS）
  3. S3 Tables・実在しないカタログの Context で、SELECT・INSERT 以外の文（EXPLAIN・CTAS・CREATE VIEW）と、
     引用符付きの部品を含む名前
  4. 既定の Context の INSERT で引用符付きの部品を含む名前
  5. 引用符付きの部品が 2 つ、4 部の列の参照に引用符付きを含む形
  6. o8 の再現（列名）と、INSERT で実際に行が入ったか（#260 は結果ファイルを保存していない）
- 継承できる事実:
  - 判定は Context の Catalog と文の種類の組だけで決まる（`unquoted_alias::by_context`）。SQL 本文に
    何を書いたか（別名キーをどう綴ったか）は判定に関係しない。したがって p3・p4（別名キーの無引用）は
    athena-local の書き換えを試す項目ではなく、本物の Trino/Athena が大文字混じりのカタログ名を
    どう解決するかを測る項目になる
  - 実在しないカタログは `context_catalog::missing` で Trino に問い合わせ、Trino にあるカタログは
    連携カタログとみなして当てない（#260 の設計判断）
  - 実測の記録は `docs/dev/measurements/statements.md` の #260 の節、未実測は `docs/dev/unmeasured.md`
    の #246・#260 の行

  の 4 + S3TABLES_* が揃うときだけの `<S3CTX>` の p17・p19・p21・p23・p24 の 5
- DDL・書き込み: 実在する表 `<PROBE>_p_real`（Hive、CTAS で 1 行）・Iceberg 表 `<PROBE>_p_ice`
  （`LOCATION` 付き、INSERT で 1 行）・ビュー `<PROBE>_p_view` を作り、全項目で使い回して最後に消す
  （trap でも保険をかける）。DELETE・UPDATE・MERGE は存在しない値（`n = 999`）を対象にした no-op で

  p1〜p4 だけ未測定にする。全体は止めない）
- 成功した SELECT（p0・p0b・p1・p3・p23〜p26・p29〜p32）は結果ファイル本体を `aws s3 cp` のリダイレクトで
  取得し、列名の行を summary に出す。成功した INSERT（p2・p4・p27・p28）は直後に
  `SELECT count(*) FROM <DB>.<PROBE>_p_real` を `<label>-count` として投げ、結果を同じ形で取得する

- ドライラン: 本物には送らず、`bash -n` と、PATH の先頭に置いた偽の `aws`（StartQueryExecution・
