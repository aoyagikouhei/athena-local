- 名前: athena-local 自身の設定は `ATHENA_LOCAL_*`（`src/config.rs:65-72`）。綴りは API の `WorkGroup` に合わせて `WORK_GROUPS`。
- 区切りはカンマ、要素ごとに `trim`（`parse_catalog_map` `src/config.rs:89-90` と同じ）。
- **空要素は起動時エラー**（末尾カンマは compose で現実に起こり、黙って通すと Grafana に空行の候補が出る。`:94-96` と同じ）。**重複は検査しない**（計画レビューの削減 1。名前の一覧に写像のような曖昧さは無く、起きるのはドロップダウンに同じ名前が 2 回出るだけ。起動を止める方が害が大きい）。
- **`parse_work_groups` で名前の辞書順にソートする**（実測で本物が名前順。`Vec<String>` を `sort()` して持つ。`HashMap` は使わない）。`Config.work_groups` は整列済みが不変条件。結合テストの足場（`tests/common/mod.rs:228` の構造体リテラル）は `parse_work_groups` を通らないので、**足場には整列済みの名前を渡し**、順序の責務は `config.rs` のユニットテストだけが持つ（計画レビュー 3-1）。
- `primary` を含めない設定を許す（自動で足さない）。一覧に無くても `GetWorkGroup` は成功し、Grafana も保存済みの名前が一覧に無くてもクエリは動く。副作用: `WorkGroup` を省いた `StartQueryExecution` は一覧に無くても `primary` になる。README の Caveats に書く。
- 名前の形式（botocore の `[a-zA-Z0-9._-]{1,128}`）は検証しない。`GetWorkGroup` でも検証していないので揃える。
- 件数の上限は検査しない（50 件超の設定は起きず、起きてもページングされるだけ）。

**`Config` の持ち方。** `pub work_groups: Vec<String>`。`parse_work_groups(env: impl Fn(&str) -> Option<String>) -> Result<Vec<String>, String>`。前置き `ATHENA_LOCAL_WORK_GROUPS: ` は関数内で付ける（`parse_retention` と同じ）。

**`DEFAULT_WORK_GROUP` の移設。** `src/config.rs` へ `pub const`（`DEFAULT_RETENTION` `:9-10` の前例）。doc:「StartQueryExecution で WorkGroup が省略されたときの既定名で、ATHENA_LOCAL_WORK_GROUPS が未設定のときに ListWorkGroups が返す唯一の名前。GetWorkGroup では使わない（WorkGroup は必須項目で、無ければ parse が弾く）。」

**`State`／`EngineVersion` の共有: 案 A。** `operation.rs` に `const WORK_GROUP_STATE: &str = "ENABLED";`（実測日コメント）と `fn engine_version() -> EngineVersion` を置き、両関数から呼ぶ。`EngineVersion` に `Clone` は足さない（案 B）。直書き + テストの突き合わせ（案 C）は crate 内 2 箇所なので共通化で足りる。issue 本文の「食い違わせない」をコンパイラで保証する。

**型（`src/athena.rs`）。** `ListWorkGroupsRequest { max_results: Option<i32>, next_token: Option<String> }`（`#[serde(default)]`、`GetQueryResultsRequest:124-131` と同じ）。`ListWorkGroupsResponse { work_groups: Vec<WorkGroupSummary>, next_token: Option<String> }`（`skip_serializing_if`。コメントに空文字だと Grafana が無限ループする旨）。`WorkGroupSummary { name, state, description: String, engine_version: EngineVersion }`（既存の `EngineVersion` を再利用）。

**`list_work_groups` の本体（50 行以内）。**

1. `parse::<ListWorkGroupsRequest>`。
2. `MaxResults` の範囲検査を **`usize` へのキャストより前に**行う（計画レビュー 1-1。キャスト後だと `-1` が巨大値になり `offset + limit` がオーバーフロー、`0` だと `end == offset` で同じ `NextToken` を返し続け Grafana が無限ループする）。`i32` のまま比較し、`< 1` は `invalid_request_with_code("1 validation error detected: Value at 'maxResults' failed to satisfy constraint: Member must have value greater than or equal to 1", "INVALID_INPUT")`、`> 50` は同じ形で `less than or equal to 50`（どちらも 2026-09-18 実測）。未指定は既定 50（**本物の既定ページサイズは未実測**。3 件しか無く測れない。botocore の `MaxWorkGroupsCount` の max に合わせ、README に未実測と書く）。
3. `NextToken` の検査。空文字は `invalid_request_with_code("1 validation error detected: Value at 'nextToken' failed to satisfy constraint: Member must have length greater than or equal to 1", "INVALID_INPUT")`（2026-09-18 実測）。それ以外で「`usize` として読めて `< names.len()`」でないものは `invalid_request_with_code(format!("The nextPageToken is malformed: {token}"), "INVALID_INPUT")`（2026-09-18 実測。受け取った値をそのまま末尾に付ける）。この規則は発行したトークン（`1 <= end < len` の 10 進）を全部受け、発行していない値のうち `"0"`・先頭ゼロ・`+` 付きも通るが、結果は正当なページと同じなので厳密化しない（計画レビュー 3-3）。`get_query_results` のような丸め（`.min(len)`）は入れない。
4. `end = (offset + limit).min(names.len())`、`next_token: (end < names.len()).then(|| end.to_string())`（`src/operation.rs:451` と同じ表現）。
5. 検査の順序は `MaxResults` → `NextToken`。両方が同時に不正なときの本物の順序は実測しない（クライアントからは起こらない）。

**直列化・エスケープ境界。** 環境変数の分割（`split(',')` + `trim`）と `NextToken` の `usize` ⇄ 文字列だけ。JSON は serde。手書きの連結は無い。厄介な入力は `config.rs` の表駆動テスト（前後空白・空要素・末尾カンマ・重複）。

**表現の正規化境界。** 該当なし。一覧と `GetWorkGroup` の名前を突き合わせない。
