### P-2 項目の表の形（Plan の案を覆した判断）
Plan の案は「TSV の 1 行 = 1 要素の配列 + SQL は `ITEM_SQL[id]` 連想配列」。**採らない**: TSV の列に空・`-` の約束が要り、id を 2 か所に書き、`IFS=$'\t' read` の境界が増える。代わりに **1 行 1 宣言の関数呼び出し**にする（bash の引数なので SQL の `'`・`"`・改行・タブはそのまま渡り、エスケープの境界が無い）:
```
item mk_h   ctx=db creates=TABLE:$T_H  "CREATE EXTERNAL TABLE $DB.$T_H (c char(10), ...) LOCATION '$LOC_H'"
item d_h    ctx=db needs=mk_h          "DESCRIBE $DB.$T_H"
item s_like_star ctx=catalog "SHOW SCHEMAS LIKE '${DB:0:3}*'"
item x_void skip="Athena の文書の変換の表に無い（querying-iceberg-creating-tables）" "…"
api  l_db   ListDatabases '{"CatalogName":"AwsDataCatalog"}'
run_items
```
- 列（key=value、省略可）: `ctx=db|catalog|none|<Catalog>/<Database>`（既定 db = `Catalog=$CATALOG,Database=$DB`）、`needs=<id>[,<id>]`（前提の項目が SUCCEEDED でなければ skip、理由「needs <id> が <state>」）、`creates=TABLE|VIEW:<名前>`（SUCCEEDED なら台帳に記録）、`skip=<理由>`（投げずに未測定として残す。要件 10）。最後の引数が SQL（api は Operation と JSON）
- `run_items`: 宣言順に実行。`ONLY=id,id` で絞る（needs の先は自動で含めない。絞った結果 needs が未実行なら skip）。`creates` の表は「その表を needs に持つ最後の項目」の直後に best_effort_drop（利用者がいなければ作った直後）。最後に finish_cleanup で DROP の終端を待つ。trap は created.tsv を読む保険（#113）
- **`lib_init <issue> <PREFIX>` が宣言の前に preflight まで済ませる**（宣言の SQL が `$DB`・`$OUTPUT`・`$RUN_STAMP` を展開するので、DB の自動選択は宣言より前に要る。6b の待ちに describe-types.sh を下書きして分かった）
- 作る前の同名確認: preflight で `SHOW TABLES` の結果に PREFIX（`athena_local_probe_<issue>`）を含めば何も作らずに止まる（describe-extended.sh:923-934 の形。probe_prefix_exists の項目ごとの確認は要らない）

### P-10 直列化・エスケープ境界
