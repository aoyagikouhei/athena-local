正常系: `MaxResults` 1 の NextToken は長さ 100 の base64 らしい文字列（不透明）。正しいトークンで 2 ページ目（5 行）が取れ、`MaxResults` 1 を付けると 2 ページ目にも NextToken が付く。`UpdateCount` は SELECT でも `0` で返る。

**確定した検証の順序**: 枠組みの検証（nextToken の空文字 → maxResults の下限。両方なら 1 文にまとめる）→ MaxResults の上限 → ID の存在 → NextToken の形。

**未実測**: (1) `MaxResults` 1001 と実在しない ID の同時（上限と存在確認の順序。stash の実装は上限を先にしている）(2) 結果の無いクエリ（FAILED／CANCELLED／RUNNING）に不正な NextToken を渡したときの順序 (3) 本物の既定ページサイズ（`MaxResults` 無しで 6 行全部返ったが、上限 1000 より小さい既定は否定できない）(4) ListWorkGroups の 2 件同時の形（#9 でも未実測。GetQueryResults と同じ枠組みのはずだが測っていない）。

### stash の実装（判定箇所と設計）
