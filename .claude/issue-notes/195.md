## 設計判断

1. **観測できる挙動は 1 つも変えない（D1）。** 既存の食い違い（`CREATE TABLE t AS (VALUES 1)` の file=Table・sub=CREATE_TABLE、`SELECT(1)`／`EXPLAIN(TYPE IO)` の UTILITY・Text、`ALTER TABLE"t"` の None）もそのまま固定テストに焼き込み、本物の値は別 issue で測る（起票）。crate は「空白とコメントで切った語」（`words`／`words_iter`）と「キーワード境界で読む `Cursor`」の両方を提供し、先頭 `(` を剥がすかどうかは判定側（athena-local）の前処理のまま。剥がし方だけ `results::strip_open_parens` 1 つに共有（`is_create_table_as` に渡す語列の剥がした／剥がしていないの違いは残す）
2. **修飾名の読み取りは `Cursor::qualified_name` 1 つに統合し、空の名前部分は None（厳しい方。ユーザーの判断 1）。** 変わるのは `ALTER TABLE cat..t ADD COLUMN c int` のような入力の `alter_table_action` だけで、本物の Trino が構文エラー（400）にするので観測できない（前提の検証 12・13。偽 Trino の結合テストには届くがそのような入力のテストは無い。実機の e2e で 400 を対照ケースとして確かめる）。固定テストは P1 で今の値を焼き、P3 で None に書き換える（P3 の red）。decisions.md に「#44 の『用途が違うので共通化しない』を #195 で変更」を書く
