## 引き継ぎ
- 判定箇所: `src/operation/quoted_names.rs` の `rejection`（呼び出し元は `src/operation/execution.rs:104`、構文チェックの直後）。`ALTER TABLE IF ...` は `if_follows("ALTER")` で今は `None` を返して実行させている（quoted_names.rs:26-32）。`no_viable_alternative(sql, at, input)` と `position` がそのまま使える
- 共有できる既存機構: `STATEMENTS` の並びと `target_table::table_name_start`、`athena_sql::Cursor`（`keyword`・`qualified_name`）、`substatement_type`（`ALTER_TABLE_ADD_COLUMN`・`CREATE_TABLE` の判定）
- 原因の仮説: 3 つとも Trino の文法では正しいので構文チェックを通り、quoted_names の対象（引用符付きの名前）でもないので実行まで届く
- 実測済み（docs/dev/measurements/statements.md の #204 節と 381 行付近）: `ALTER TABLE IF EXISTS t ...` → `line 1:16: no viable alternative at input 'ALTER TABLE IF EXISTS'`（引用符の有無によらず）、`ALTER TABLE t ADD COLUMN m int` → `line 1:45: no viable alternative at input 'ALTER TABLE <t> ADD COLUMN'`、`CREATE TABLE x (n int)` → `No location was specified for table. An S3 location must be specified`（位置なし）
- 未実測・未確認:
  - no viable alternative の位置と input の範囲の規則（先頭コメント・改行・小文字・名前の部品数・`IF EXISTS` の後ろの名前の有無）。既存の ALTER の規則（文の最初の語から問題の語の終わりまで）と同じかどうか
  - ADD COLUMN 単数の後ろに `IF NOT EXISTS`・`COMMENT` などが続く形、`ADD COLUMN` 以外の Trino 専用の ALTER（`SET PROPERTIES`・`EXECUTE`・`SET AUTHORIZATION` など）が本物でどうなるか

  - Context のカタログが実在しないとき（#217 で CREATE_TABLE・ALTER_TABLE_ADD_COLUMN を差し替え対象にした）との順序
