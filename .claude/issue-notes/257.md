## 実測の手順

- 実行例（`tools/dev.sh` 経由。DB を省略するか実在しなければ SHOW DATABASES の候補の 1 件目を自動で使う）:
  ```
  tools/dev.sh OUTPUT=s3://your-bucket/prefix/ DB=your_db ROUND=3 bash tools/measure/block-comment-parse-error.sh
  ```
  S3 Tables・連携カタログの項目まで測るなら:
  ```
  tools/dev.sh OUTPUT=s3://your-bucket/prefix/ DB=your_db ROUND=3 \
    S3TABLES_CATALOG=s3tablescatalog/your-bucket S3TABLES_NS=your_ns S3TABLES_TABLE=your_table \

  ```
  資格情報はホストのシェルで `AWS_ACCESS_KEY_ID` などを export してから（または `~/.aws/credentials`）。
- 必須の環境変数: `OUTPUT`（`s3://bucket/prefix/` の形、末尾に `/`）。
- 任意の環境変数: `DB`・`CATALOG`（既定 AwsDataCatalog）・`REGION`（既定 ap-northeast-1）・`OUT_DIR`・`POLL_TIMEOUT`・`RETRY_MAX`・`RETRY_DELAY`（スクリプト先頭のコメントに詳細）。加えて ROUND=3 専用: `S3TABLES_CATALOG`・`S3TABLES_NS`・`S3TABLES_TABLE`（S3 Tables。3 つとも揃っていなければ s3t1・s3t2 は未測定）、`FEDERATED_CATALOG`・`FEDERATED_DB`・`FEDERATED_TABLE`（連携カタログ。3 つとも揃っていなければ fc1 は未測定。このアカウントに連携カタログが登録されていなければ未設定のままでよい）。
- 出力先: `${DEV_HOST_HOME:-$HOME}/athena-block-comment-parse-error-measurements/run-<日時>/`（リポジトリの外）。`summary.txt` が実名をマスクした、そのまま貼れる一覧。
- 呼び出し回数: フィクスチャ（H・I・V の作成 3 回・SHOW CREATE TABLE での形式裏取り 2 回）+ 項目 21〜24 回（S3TABLES_*・FEDERATED_* が揃っていれば 24、揃っていなければ 21。未測定分は呼ばない）+ 後始末（DROP 3 回 + Iceberg の RENAME 先の後始末 2 回）。ドライラン（偽 `aws`）で確認した実測値: 環境変数なしで 32 回、S3TABLES_*・FEDERATED_* を全部渡すと 35 回。
- 課金と DDL: あり。フィクスチャは ROUND=1 と同じ 3 つ（`athena_local_probe_244_h`・`_i`・`_v`）を作り、最後に DROP する。ri1（Iceberg の DROP COLUMN）は I の唯一の列 `n` を消し、ri2・ri3（Iceberg の RENAME TO を先頭・TABLE の後の位置で 2 回）は成功すると I を `athena_local_probe_244_i_ren3a` → `_ren3b` の順に移す（後始末はこの 2 つの名前にも DROP TABLE IF EXISTS を投げる）。r1（REPLACE COLUMNS）・r3（CHANGE COLUMN）は H の列の構成を変えうるので、列 `n` を使うほかの項目（pos1・nc2）より後に置いた。スキャンする SELECT は投げない。S3 Tables・連携カタログの項目は既存の表を読むだけで新しく作らない。

### 今の athena-local の扱いと違うもの（開発で直す候補）
1. **pos1**: `ALTER /* c */ TABLE awsdatacatalog.<DB>.<t> DROP COLUMN` の ErrorMessage は、落とした後の文の `mismatched input 'COLUMN' ...` ではなく、
   **受け取ったままの文で `no viable alternative at input '<表名の直前まで>'`（位置は表名の先頭）**。Query も受け取ったまま（落とさない）。
   athena-local は「落とした後の文で数える」としていた（#257 本文の表）
2. **msck1・msck2**: `MSCK REPAIR TABLE awsdatacatalog.<DB>.<t>` は本物では SUCCEEDED で、Query から `awsdatacatalog.` が落ちる（#242 の落とす文に
   MSCK REPAIR TABLE も入る）。無い表でも SUCCEEDED（`Tables not in metastore`）。athena-local は落とさずカタログとして引き、無ければ構文エラーにしていた
3. **e3**: 先頭コメントの中身が `||` のとき、3 語目は `'|'`（1 文字）。`<=`・`!=` は 2 文字で出る。e5 の閉じていない引用符は `'a'`（引用符を落とす）
