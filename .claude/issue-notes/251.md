### CTAS が DB 無しで FAILED のときの付随物（r4・r5・r6b・r7b・r8a・r8c で同じ）
- OutputLocation は `<OUTPUT>tables/<id>`（拡張子無し）。その場所に:
  - `<id>.metadata`（81 バイト）: 中身は Trino のクエリ ID・`CREATE TABLE`・列 `rows` bigint の protobuf（項目の間ではクエリ ID だけが違う。成功した CTAS の `.metadata` とは今回突き合わせていない）
  - `<id>-manifest.csv`（155 バイト）と、データファイル `<id>/<Trino のクエリ ID>_<uuid>`（257 バイト。1 行分）が**残る**（理由の文言どおり Athena は消さない）
  - 結果ファイル本体（`<OUTPUT>tables/<id>`）は無い（404）
- ScannedBytes は 0

### 読み取れる規則（実装への含意）
- 名前空間が無いときの `Cannot find or access the specified table`（2 / 1100）は、名前の部の数（1・2・3 部）と `IF NOT EXISTS` の有無によらない
- `IF NOT EXISTS AwsDataCatalog.<ある名前空間>.<t>` は作れる（#237 の扱いのままでよい）
- `awsdatacatalog.<DB>.<t>` の CTAS は、Context（既定・S3 Tables）・綴り（大文字小文字）・`IF NOT EXISTS` によらず、DB があれば成功、無ければ
  `Database <小文字の DB 名> not found ...`（2 / 1301）の FAILED。athena-local は「名前は書いたとおり」としているので、**小文字にする**よう直す候補。
  FAILED でも `.metadata`・manifest・データが置かれる（athena-local は `.metadata` を置かない。直す候補）
