## 設計判断

1. **構成 A**: ルートの `Cargo.toml` に `[package] athena-local` を残し、`[workspace] members = ["crates/athena-sql"]`・`default-members = [".", "crates/athena-sql"]` を足す。
   理由: 既存のコマンド（CLAUDE.md・docs・ci.yml）、release スキル（`grep '^version' Cargo.toml`、lock の 1 行差分）、e2e の `BINARY` パスを 1 つも変えずに workspace 全体へ効く（統括役の実験）。
   仮想 workspace（B）は `src/`・`tests/` の移動だけで大きな差分になり、`--test` や release の手順の意味が変わる。
2. **crate の版は `0.1.0` 固定で継承しない**（`[workspace.package]` も作らない）。理由: release SKILL.md:54-55/:113 が lock の差分を athena-local の 1 行だけと前提にしている。版を本体と同じにすると SKILL.md:49-51 の grep にも当たる。
3. **crate の中身はモジュール doc だけ**（関数もプレースホルダのテストも置かない）。「crate のテストが走る」は `cargo test` の出力に crate の unittests の行（`Running unittests src/lib.rs (…/deps/athena_sql-<hash>)`。cargo は package 相対のパスで出す）と `Doc-tests athena_sql` の行が出ることで確かめる（足場 4a）。
4. **CI・toolbox のキャッシュは変更不要**（issue 本文の「合わせる」は調査の結果、合わせるものが無い）: rust-cache の既定 `. -> target` と全 Cargo.toml/lock のハッシュ key、toolbox の `hashFiles('Cargo.lock')` は lock がルートに 1 つのまま、docker.yml に cargo のキャッシュは無い。→ 「覆した事前判断」に記録。
5. **CHANGELOG・README・docs/*.md は変えない**（decisions.md:24。挙動が変わらない）。「crate の版は追わない」は decisions.md に規則として書く。
6. **decisions.md:5「重ねない」との折り合い**: 規則の本文は CLAUDE.md:74 に残し、decisions.md には理由だけを書く（:30・:61 の「理由を CLAUDE.md から移した」と同じ形）。:5 は変えない。
7. crate 名は issue の仮名 `athena-sql`（package）／`athena_sql`（lib）をそのまま使う → **6b でユーザーに確認**（仮名と書かれているため）。
