## 実測の手順
- スクリプトのパス: `tools/measure/block-comment-parse-error.sh`（issue #244 で作成。

  形の測り直し（下の「ROUND=5」）。
- 実行例（`tools/dev.sh` 経由。DB を省略するか実在しなければ SHOW DATABASES の候補の
  1 件目を自動で使う）:
  ```

  ```

  ```
  tools/dev.sh OUTPUT=s3://your-bucket/prefix/ DB=your_db ROUND=4 \
    S3TABLES_CATALOG=s3tablescatalog/your-bucket S3TABLES_NS=your_ns S3TABLES_TABLE=your_table \
  ```

  `~/.aws/credentials`）。

  （リポジトリの外）。`summary.txt` が実名をマスクした、そのまま貼れる一覧。

  65 個ぶん（S3TABLES_*・FEDERATED_* が揃っていれば全 65 回、揃っていなければ群 F の
  4 項目が未測定になり 61 回。ただし RENAME TO が決め手の位置にある項目
  （pn5・ar_h0・ar_h2 は H、ar_v0・ar_v2 は V）はどれか 1 つが成功すると後続が
  「改名済みのため未測定」で skip になり、その分だけ呼び出しが減る）+ 後始末

  RENAME TO 系がカスケードで 3 件 skip になった分だけ理論上限の 79 から減った）。

### 群 C（先頭コメントの字句。`SHOW CREATE TABLE <DB>.<H>` に載せた）
- 先頭（`/* X */ SHOW ...`）: `>=`・`<>`・`==`・`<=`・`!=` のどれも 3 語目は 2 文字のまま（`line 1:0 cannot recognize input near '/' '*' '>='` など）、1/1003
- 名前の直前（`SHOW CREATE TABLE /* X */ <DB>.<H>`）: 同じく 2 文字のまま（`line 1:18 ... '>=' in table name` など）
- ROUND=3 の e3（`||` は `'|'` の 1 文字）と合わせると、2 文字で出るのは `<=`・`!=`・`>=`・`<>`・`==`、1 文字は `||`
- `lex_quote_later`・`lex_quote_later_name`（`/* 'a */ ALTER TABLE <H> SET LOCATION '...'`・`ALTER TABLE /* 'a */ <H> SET LOCATION '...'`）は
  どちらも SUCCEEDED。**SET LOCATION はコメントがあっても成功する文（ROUND=3 の r2）なので、閉じていない引用符の字句はこれでは測れていない**（ROUND=5 で ADD COLUMNS に載せて測り直す）

### 群 D（awsdatacatalog. 付き 3 部の名前とコメント）
- ADD COLUMNS（aa_*）: 先頭は `line 1:0 cannot recognize input near '/' '*' 'c'`、TABLE の後は `line 1:12 ... in table name`、1/1003。H・V・無い表で同じ。
  **Query は `awsdatacatalog.` が落ちる**（pos1 の DROP COLUMN が受け取ったままなのと逆）。位置は名前より前なので、落とす前・後のどちらで数えても同じ値で区別できない（ROUND=5 の群 P で名前の後ろに置いて測る）
- RENAME TO（ar_*。改名先も `awsdatacatalog.<DB>.<new>`）: どれも**開始時**に `line 1:111: mismatched input '.' expecting <EOF>`（MALFORMED_QUERY。無い表は 1:117）。
  111 は改名先の 2 つ目の `.`（受け取った文の 0 始まり 110）の 1 始まりの列。**改名先の 3 部の名前が開始時の構文エラーになる**ことは分かったが、元の名前だけに
  `awsdatacatalog.` が付いた RENAME は測れていない（ROUND=5 の群 R で改名先を 2 部にして測る）

### 群 E（#256。コメント無しの `ALTER TABLE awsdatacatalog.<DB>.<H> DROP COLUMN n`）

### 今の athena-local の扱いと違うもの（開発で直す候補）
1. **Iceberg 表**: `SHOW CREATE TABLE <DB>./* c */<I>` と `ALTER TABLE <DB>.<I> /* c */ ADD COLUMNS`・`DROP COLUMN` は SUCCEEDED。MSCK・REPLACE COLUMNS は
   `Query type not supported by Athena Iceberg at this time`（2/1200）、`DESCRIBE EXTENDED` は `EXTENDED keyword is not supported for Iceberg tables.`（2/1100。#275 にも効く）
2. **ビュー・無い表**: 群 A の 6 形とも H と同じ ParseException（今は Hive 表だけ失敗させ、ほかは Trino に送っている）
3. **位置**: 群 B の各位置は、`/` の位置の ParseException（ALTER の REPLACE COLUMNS・CHANGE COLUMN・RENAME TO は ErrorMessage が `Query type not supported by DDL engine.`、
   DROP COLUMN は `mismatched input 'COLUMN'`）。`DESCRIBE FORMATTED /* c */` は EXTENDED と違う `missing EOF at '/' near 'FORMATTED'`
4. **字句**: `>=`・`<>`・`==` も 2 文字（今は `<=`・`!=` だけ 2 文字）
5. **群 E**: コメント無しの `ALTER TABLE awsdatacatalog.<DB>.<t> DROP COLUMN` は受け取った文で `no viable alternative`、Query は受け取ったまま
6. **Query**: DESCRIBE EXTENDED／FORMATTED はビュー・無い表でもコメント越しに DB が落ちる。`awsdatacatalog.` 付きの ADD COLUMNS と MSCK（コメントが `awsdatacatalog.` の直後でも）は
   `awsdatacatalog.` が落ちる。DROP COLUMN（pos1・群 E）だけ落ちない
7. AthenaError の型: ALTER の REPLACE COLUMNS・CHANGE COLUMN・DROP COLUMN・RENAME TO は 2/1006、ADD COLUMNS・SHOW CREATE TABLE・MSCK・DESCRIBE は 1/1003
