## 事前に確認した事実
### 過去の実測（調査 3）
1. 末尾の `;` だけの SELECT（#228 の k6〜k12・k28、#76 の g2-semicolon）はすべて SUCCEEDED・DML/SELECT・`.csv`。GetQueryExecution の `Query` は末尾の `;` を前後の空白・改行・CR・続く `;` ごと落とした形: `SELECT 1;;`・`SELECT 1; ;`・`SELECT 1; `・`SELECT 1;\n\n`・`SELECT 1 ;`・`SELECT 1;\r\n` → `SELECT 1`、`-- c\nSELECT 1;` → `-- c\nSELECT 1`、`SELECT 1 -- c\n;` → `SELECT 1 -- c`
2. g2-semicolon の `.csv`（12 バイト、binary/octet-stream）と `.metadata`（81 バイト）は `SELECT 1` とバイト列が同じ（QueryExecutionId 由来の差だけ）
3. `CREATE TABLE <db>.<t> (n int);`（k27）は `;` の無い形と同じ No location
4. 未測定: 先頭の `;`、`SELECT;`、`DESCRIBE <無い表>;`、S3 Tables の Context の 2 catalogs に `;`、`(n int NOT NULL);` の NV、`SHOW TABLES;`、CTAS・INSERT・EXPLAIN の末尾 `;`、`SELECT ?;`（パラメータ付き）。`;` の無い文の末尾の空白が `Query` で落ちるかも未測定

### 書き換えの約束と足場（調査 2）
1. CLAUDE.md:36 の不変条件「書き換えの条件（パラメータ、別名）に当たらなければ Trino に送る SQL は 1 文字も違わない。条件を足したらこの一覧と docs/configuration.md の "not rewritten" も直す」、CLAUDE.md:75「書き換えは本物がそう扱うと実測した場合だけ。範囲の差し替えだけ。書き換えた SQL は実行の中だけに置き、Store の Query は受け取ったまま」
2. docs/configuration.md:27-30 "Without `ExecutionParameters` the SQL string is not rewritten, except for catalog aliases"。docs/api.md:123 に「末尾の `;` だけの文は構文チェックで落ちる」（#228 で書いた。今回直す）、docs/caveats.md の "A trailing `;`" の項（#228）
3. decisions.md:73 の 4 つの理由のうち (4)「Query を受け取ったまま返す（docs/parameters.md で約束）。書き換えた SQL は実行の中のローカル変数にだけ置き、Store には保存しない」。decisions.md:75「書き換えの条件を足したら CLAUDE.md と configuration.md を同じ PR で直す」（#235）
4. 既存の書き換え: `catalog::alias_qualified_names`（execution.rs:383 の実行直前と completion.rs:25 だけ。構文チェック execution.rs:83 と Store・GetQueryExecution の Query（query_execution.rs:165、StatementType も同じ生の query から）は受け取ったまま）。パラメータは statement.rs の EXECUTE IMMEDIATE で包む
5. 「1 文字も違わない」の保証は `trino_sqls()`・`syntax_checks()` の完全一致の結合テスト群（tests/syntax.rs:88 など）と catalog.rs:225 の Cow::Borrowed
6. 偽 Trino（tests/common/mod.rs:494-538）は構文を見ず、`;` 付きでも成功を返す。本物の Trino の `;` の拒否を再現するには syntax_check_response を明示する
- 落とした: 調査 2 の 7（architecture の判定の対の一覧。今回は判定を変えないので計画で要るときに引く）
