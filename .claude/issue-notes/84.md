## 設計判断

1. **本文の解釈を新モジュール `src/request.rs` に置く**（`response.rs` は「レスポンスの組み立て」で、`parse` だけが場違いだった。`catalog.rs`／`failure.rs` と同じ 1 関心 1 ファイル）。`response.rs` には `__type` だけの応答を作る `bare_error(code)` と `serialization_error(Option<String>)` を足す。工学判断
2. **`parse` は 3 段で読む**: (a) `serde_json::Value` として読めなければ `SerializationException`（`Message` 無し）(b) トップレベルが配列なら `Start of list found where not expected`、object 以外のスカラは `Message` 無し (c) object の `null` の項目を消し、小数を整数に切り捨ててから `from_value::<T>`。失敗は serde のエラー文の先頭で分ける: `missing field `X`` → 枠組みの検証（`Value null at '<lowerCamel(X)>' ... Member must not be null`。`validation.rs` の `validation_errors` を `pub(crate)` にして共有）／`invalid type: <found>, expected <expected>` → 実測の表の文言／それ以外（`invalid value`・`invalid length`）→ `Message` 無し
3. **文言は実測した組み合わせだけ出し、未実測の組み合わせは `Message` 無しの `SerializationException` にする**（CLAUDE.md「実測していない振る舞いは推測で埋めない。項目を省く」）。`false`→`FALSE_VALUE` は自然な類推だが未実測なので出さない。README の Caveats に書き、起票する
4. **`MaxResults` を `Option<i32>` から `Option<i64>` にする**（`athena.rs` 2 箇所、`validation.rs`、定数 2 つ）。Integer の範囲外を本物は上限の検証エラーにする（ケース 8）ので、serde の `invalid value` にせず既存の上限の検査に流す
5. **ディスパッチは `UnknownOperationException`（`Message` 無し）に揃え、前置き `AmazonAthena.` を必須にする**（`trim_start_matches` → `strip_prefix`）。README に前置き無しを許す記述は無く、SDK は必ず前置きを付ける。既存テスト `tests/dml.rs:165` を新しい形に直す
6. **`Content-Type` は見ない**（本物の 200 別形式／404 XML は揃えない。Caveats に 1 文）
7. `ClientRequestToken` 無しの自前の文言（`clientRequestToken is null or empty`）は変えない（実測どおりで、parse の後に見る順序も本物と同じ: ケース 38 は `queryString` の欠落が先）

`parse` の擬似コード:

```
let value: Value = from_slice(body) else → serialization_error(None)
if value is Array → serialization_error(Some("Start of list found where not expected"))
if value is not Object → serialization_error(None)
let value = normalize(value)   // object の null の項目を消す（入れ子の object も）。小数の切り捨ては入れない（計画レビュー 3）
from_value::<T>(value).map_err(|e| deserialize_error(&e.to_string()))

deserialize_error(text):
  "missing field `X`"  → invalid_request_with_code(validation_errors(&[format!("Value null at '{lower_camel(X)}' failed to satisfy constraint: Member must not be null")]), "INVALID_INPUT")
  "invalid type: <found>, expected <expected>" → serialization_error(type_mismatch(found, expected))
  それ以外 → serialization_error(None)

type_mismatch(found, expected) -> Option<String>:   // 実測した組み合わせだけ。それ以外は None（Message 無し）
  expected が整数（i64 など）か "a string" のとき:
    found が "sequence"  → "Start of list found where not expected"
    found が "map"       → "Start of structure or map found where not expected."
    found が "string …"  → 整数なら STRING_VALUE can not be converted to an Integer（String は正常なので来ない）
    found が "integer …" → "a string" なら NUMBER_VALUE can not be converted to a String
    found が "boolean `true`" → 整数なら TRUE_VALUE … an Integer／"a string" なら TRUE_VALUE … a String
  expected が "a sequence" で found が "string …" → "Expected list or null"
  expected が "struct …" で found が "string …"  → "Expected null"
  それ以外（false・null・floating point・map → sequence など）→ None
  注: 配列 → 入れ子の構造体（ケース 37）は serde の derive が空の配列を空の struct として受けるので、ここには来ず 200 になる（計画レビュー 1。揃えない。Caveats と起票）
```
