### 未実測（実測スクリプトに全部入れる。#83 の `83-measure-raw-get-query-results.py` を雛形にして、SigV4 自前署名で送る）

- 壊れた JSON（`{` だけ、空の本文、JSON でない文字列）
- 数値 → 文字列（`QueryExecutionId: 1`、`WorkGroup: 1`、`QueryString: 1`）、真偽値 → 整数（`MaxResults: true`）、小数 → 整数（`MaxResults: 1.5`）、`null`（`MaxResults: null`）、文字列 → 配列（`ExecutionParameters: "x"`）、配列 → 文字列、オブジェクト → 文字列（`QueryString: {}`）、文字列 → オブジェクト（`ResultConfiguration: "x"`）。文言の `STRING_VALUE`／`Integer` の部分が JSON の型と目的の型でどう変わるか

- 未知のキー（`{"QueryExecutionId": ..., "Foo": 1}`）が無視されるか

### 原因の仮説と直し方の候補

- `serde_json::Error` は `classify()` で `Syntax`／`Data`／`Eof`／`Io` に分かれるが、型違いと必須キー欠落はどちらも `Data`。見分けるなら `e.to_string()` の先頭（`invalid type: ...` と `missing field ...`）を見る。型違いの文言 `STRING_VALUE can not be converted to an Integer` は JSON の型（`STRING_VALUE`）と目的の型（`Integer`）を含むので、他の組み合わせを実測してから対応表を作る
- 必須キー欠落は本物が枠組みの検証（`1 validation error detected: Value null at '<lowerCamel>' ... Member must not be null`）なので、`validation.rs`（#83）の形に寄せられる可能性がある。ただしフィールド名の lowerCamel 化が要る
- 見分けられない・文言が揃えられない組み合わせは README の Caveats に「未実測」と書くだけにする（issue の候補どおり）
