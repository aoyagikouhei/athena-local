# #204 引用符付きの名前を取る DESCRIBE・SHOW CREATE TABLE・ALTER TABLE・DROP TABLE を本物は開始時に弾く

## 基本情報

- 出どころ: #200 の実測（run-20260925-055931、`tools/measure/keyword-boundary.sh`）。結果は `docs/dev/measurements/statements.md` の「引用符付きの名前は空白の有無によらず開始時に弾かれる」

- A2 SQL の中身を athena-local 独自に見て 400 にする箇所は今は 0（request.rs は JSON だけ、validation.rs はページングだけ）

- A5 決定: decisions.md:73「SQL の本文は書き換えない」理由 (3)「SQL の解釈を持たない。正しさは Trino と実測した Athena が決める」、:65「crate は SQL が正しいかどうかを判定しない」。弾く判定を足すのはこの 2 つに触れる（判定の規則は athena-local 側に置き、crate は読むだけなら :65 と両立）
### 引用符付きの名前を前提にした既存（Explore B）
- B1 `TRINO_CATALOG_MAP` の別名は引用符付きのカタログ名だけを置換（`src/catalog.rs`）。これを使う結合テスト `tests/table_format.rs:161-198`（`DROP TABLE "s3tablescatalog/my-bucket".ns.t` が SUCCEEDED）と `tests/describe.rs:311-342`（`DESCRIBE "s3tablescatalog/b".ns.t`）。**引用符付きの先頭部を一律に弾くと S3 Tables の DESCRIBE・DROP TABLE が使えなくなる。本物が `"s3tablescatalog/…".ns.t` を受けるかは未実測**

### 実測の足場（Explore C）
- C1 雛形 `tools/measure/keyword-boundary.sh`。開始時に弾かれた文言の全文を実名マスクで summary に出す節（:797-804）がある。後始末は `run z-drop-*`（無引用 + IF EXISTS）に揃えれば結果を確かめられる
- C2 文言の手がかり: Trino 系は `mismatched input 'X'. Expecting: ...`、Hive 系は `no viable alternative at input`・`mismatched input '...' expecting {...}`（小文字・波括弧）・`ParseException`。`Queries of this type are not supported` は `SELECT FROM` でも出る汎用の拒否
- 落とした番号: A-7（api.md の構文エラーの段落。docs 更新時に見る）、C-6（development.md の流し方。既知）
- 16:24 手元の Trino 482（memory カタログ）: 受ける `DESCRIBE "t"`・`DESC "t"`・`SHOW CREATE TABLE "t"`・`SHOW COLUMNS FROM "t"`・`ALTER TABLE "t" ADD COLUMN m int`・`DROP TABLE "t"`・`DROP TABLE IF EXISTS "nope"`・`DESCRIBE "default"."t"`・`DESCRIBE default."t"`。弾く `ALTER TABLE "t" ADD COLUMNS (m int)` と無引用の `ALTER TABLE t ADD COLUMNS` はどちらも `line 1:21: mismatched input 'COLUMNS'. Expecting: '.', 'ADD'`（本物が引用符付きに返した文言と同じ形。本物は無引用なら成功）、`ALTER TABLE "t" SET TBLPROPERTIES`・`SHOW TBLPROPERTIES "t"` も構文エラー
  - → ALTER TABLE "t" ADD COLUMNS は athena-local も今すでに（Trino の構文チェックで）弾いている。差は DESCRIBE・DESC・SHOW CREATE TABLE・DROP TABLE の 4 種。#200 の docs/caveats.md が「5 種は実行する」と書いたのは ALTER について誤り（この issue で直す）
- 16:21 src に「Queries of this type are not supported」を返す経路は無い（grep 0 件）。過去の実測の生データ（~/athena-*-measurements の Query と .sql）に、引用符付きの名前でこれらの文を投げた記録は #200 以外 0 件

### 方式（Plan 項目 1。仮）
- 判定は新しいモジュール `src/operation/quoted_name_reject.rs`（純関数 `check(query) -> Option<String>`。文言を返す）。`execution.rs` の構文チェック（:73-77）の直前で呼び、Some なら `invalid_request_with_code(message, "MALFORMED_QUERY")`。構文チェックと同じ枠（トークン → OutputLocation の後、`Store::submit` の前）なので、検証順・冪等・パラメータ（元の SQL で見る）・別名置換（置換前の SQL を見る）の前提を変えない
- 読む道具は既存の `athena_sql::Cursor::keyword`・`qualified_name`・`NamePart.text`（引用符付きかは先頭の `"`）・`at_end`・`skip_leading_trivia`。crate には足さない（decisions.md:65 と両立。規則は athena-local 側）
- classification.rs には足さない（分類と「開始時に弾く」は別の関心）
- ALTER TABLE "t" ADD COLUMNS は対象外（Trino の構文チェックが本物と同じ文言で弾く）

### 文言（#200 の生データで確認済み。Plan が summary.txt:79-96 から）
- `DESCRIBE"t"` → `line 1:9: no viable alternative at input 'DESCRIBE"t"'`、`DESCRIBE "t"` → `line 1:10: …'DESCRIBE "t"'`、DESC も同じ形（1:5／1:6）
- `SHOW CREATE TABLE"t"`／空白あり → `Queries of this type are not supported`（位置なし）
- `DROP TABLE"t"` → `line 1:11: mismatched input '"t"' expecting {'SELECT', 'FROM', … , IDENTIFIER, BACKQUOTED_IDENTIFIER}`（約 180 語の一覧。生データから機械的に転記して定数にし、diff で突き合わせる）、空白ありは `line 1:12`
- 位置は「引用符の開始バイト位置 + 1」（1 行・ASCII の範囲で 3 種共通）。`input '…'` は文頭から名前の終わりまでの元の SQL
