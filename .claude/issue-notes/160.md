## 設計判断
1. **UpdateCount は完了時に決めて Store に持つ。** `run` の `engine_ddl` は Store に残らず、読む側で形式が分からない（事実の 2・3 行目）。`Outcome.update_count` に載せる案は result_set.rs:10 が DML の形に使うので不可。`Store::finish` の引数を `Result<(Outcome, Option<i64>), Failure>` にし、`Execution.update_count: Option<i64>` を足す（None = 省く）。読む側は `execution.update_count` を返すだけ。判定関数 `update_count(query, &outcome, engine_ddl)` は **execution.rs に移し**（`split_explain_rows` と同じ「完了時に決めて finish に渡す」側。query_execution.rs への逆向きの依存を作らない。計画レビュー 3-(1)）、`spawn_query` で **`write_result` に `outcome` を move する前に**計算する（同 1-(2)）。EXPLAIN の前例（decisions.md:124）と同じ形。Store は `Option<i64>` を持つだけで operation の型に依存しない。
2. **省く条件は `content_type::carries_execution_id(query)`（DESCRIBE／DESC／SHOW CREATE TABLE）で、例外は `engine_ddl` が `ShowCreateTableIceberg` か `DescribeIceberg`（→ 0）。** `.txt` の Content-Type と `.metadata` の先頭 ID を決めている述語と同じにし、判定を増やさない（本物でも Content-Type と UpdateCount の有無は一致。事実の 8 行目）。`DESC` は `substatement_type` が None だが Content-Type と同じ側に倒す（design-checklist:15 の「同じ形の入力で守る」）。実測で DESCRIBE×Iceberg が 0 だったので、**DESCRIBE にも形式の問い合わせを足す**（設計判断 5）。
3. **S3 無効でも SHOW CREATE TABLE は形式を問い合わせる**（decisions.md:117 を SHOW CREATE TABLE について覆す）。問い合わせの結果を UpdateCount が使うようになるため、省くと `ATHENA_LOCAL_RESULTS=none` で Iceberg の SHOW CREATE TABLE が null になり本物とずれる。DROP TABLE／ALTER TABLE は今までどおり（結果ファイルにしか効かない）。tests/syntax.rs:146 の期待（SQL 1 本）を 2 本に直し、ddl.md:49-51 と decisions.md:117 を更新する。**人間の判断が要る論点**（運用: none モードで Trino への往復が 1 回増える。#39 の決定を覆す）。
4. 判定できない SHOW CREATE TABLE／DESCRIBE（未知のコネクタ・テーブル無し・問い合わせ失敗・名前が解析できない）は Hive 扱い（null）。ddl.md:83-86 の既存の扱いに揃える。
5. **DESCRIBE を `TargetStatement::Describe` として形式の問い合わせの対象に足す。** `substatement_type` の `DESCRIBE_TABLE` から決める（`DESC` は None のまま → 問い合わせず null。未実測）。`target_table::keywords` を「`TABLE` を含む並び」に変え（DROP TABLE／ALTER TABLE／SHOW CREATE TABLE／DESCRIBE）、`table_name_start` の固定の `TABLE` を外す（計画レビュー 1-(1) の指摘）。`DESCRIBE EXTENDED t` などは `extended` を名前として読んで問い合わせ、見つからず null に倒れる（本物は未実測。unmeasured へ）。`engine_ddl(Describe, Iceberg) => Some(EngineDdl::DescribeIceberg)`。
6. **DESCRIBE × Iceberg の本体・`.metadata` も SHOW CREATE TABLE × Iceberg と同じく binary/octet-stream・先頭はエンジン ID にする（推奨。人間の判断が要る論点）。** 実測で同じ群と分かり、機構は #151 のものをそのまま使える（result_output.rs:46-50 の match に腕を足すだけ）。issue 本文の範囲（UpdateCount）を超えるので Step 6b で聞く。含めないなら起票。
