# #278 既定の Context の Hive の CREATE TABLE ... LOCATION を開始時に弾く境界を本物で測る

## 出どころ

- issue #278。#266 の先行実測（2026-09-27、`tools/measure/unquoted-ddl.sh` の ROUND=13・14、
  生データ `$HOME/athena-unquoted-ddl-measurements/run-20260926-221348`・`run-20260926-223637`）で
  分かった、**既定の Context**（`Catalog=AwsDataCatalog`）の Hive の `CREATE TABLE ... LOCATION` の
  答え。#266 は S3 Tables の Context の判定（`hive.rs`）の条件を外すところまでにし、こちらは
  別 issue にした（判定も配線も S3 Tables の外で新しく、`start_checks.rs` の先頭を触るため）
- 本物の振る舞い（実測済み。ROUND=13・14 と、#271 の節の q12）:

  | 形（Context） | 本物 |
  |---|---|
  | `CREATE EXTERNAL TABLE <G>.<db>.<t> (n int) LOCATION '..'`（既定。<G> は実在する別のデータカタログ） | 開始時 `Unsupported ddl with 2 catalogs: <文>`（MALFORMED_QUERY） |
  | `CREATE EXTERNAL TABLE {AwsDataCatalog.<db>, <db>, awsdatacatalog.<db>}.<t> ... LOCATION`（既定） | SUCCEEDED |
  | Context が `<G>` なら `<G>.<db>.<t>`・`AwsDataCatalog.<db>.<t>`・`<t>` の EXTERNAL + LOCATION | SUCCEEDED（2 catalogs にならない） |
  | `CREATE TABLE {AwsDataCatalog, <G>}.<db>.<t> (n int) [STORED AS PARQUET] LOCATION '..'`（既定か `<G>`。EXTERNAL 無し） | `External keyword required for table type HIVE` |
  | `CREATE TABLE awsdatacatalog.<DB>.<t> (n int) LOCATION '..' TBLPROPERTIES ('table_type'='ICEBERG')`（EXTERNAL 無し） | SUCCEEDED（q12） |
  | 実在しないカタログの 1 部目 | `Catalog '<x>' does not exist`（DATACATALOG_NOT_FOUND。測り直さない） |

- 今の athena-local: 既定の Context の Hive の DDL（`EXTERNAL`・`LOCATION`）には判定が無く、
  Trino の構文チェックの構文エラーを返す（`docs/caveats.md` に既知の差として書いてある）。1 部目が
  Trino に無いカタログなら `location_catalog`（#248・#266）が DATACATALOG_NOT_FOUND で先に弾く
- 継承できる事実:
  - Hive の `CREATE TABLE` の読み方は `src/operation/unquoted_ddl/create_table/hive.rs` の `read`
    （EXTERNAL・名前の部・LOCATION などを読める）。S3 Tables の Context の判定
    （`s3_tables_rejection`）は `src/operation/start_checks.rs` の `decide` の先頭
    （`location_rejection` の直後）で呼ぶ
  - 2 catalogs の文言は `src/operation/unquoted_ddl/create_table.rs` の `TWO_CATALOGS`
    （小文字の `ddl`、`: <文>` は前後の空白だけ落とす）と同じ形
  - 「実在する別のカタログ」を手元でどう決めるかは設計判断が要る（`TRINO_CATALOG_MAP` の別名の
    キー・Trino にあるカタログ。#248 の `location_catalog` は Trino に有無を問い合わせる）
- 推奨する経路（issue 本文）: #257 のマージ後に implement-issue の小規模経路（`hive.rs` に既定の
  Context 用の判定を足し、`start_checks.rs` の先頭で呼ぶ）。#270（S3 Tables の Context の
  ROW FORMAT など、同じく `start_checks.rs` の配線が要る）と順に進めるとよい
- このラウンド（ROUND=21）で測る境界（実装が読む分岐点）: 「2 catalogs」判定と「External keyword
  required」判定それぞれの範囲（句・空白・コメント・大小文字・引用符・NOT NULL・DB 無し・2 部の
  名前でどちらが先に効くか）、Context の Catalog 省略、S3 Tables の Context での小文字
  `awsdatacatalog` の扱い、Iceberg の TBLPROPERTIES の判定境界、S3 Tables のカタログを引用符付きの
  別カタログとして書いた形。<G> が要る項目は、連携カタログ（FEDERATED_CATALOG か
  CREATE_GLUE_CATALOG=1）が無ければ項目ごとに未測定で skip する
