# #271 CREATE EXTERNAL TABLE の 3 部の名前で、GetQueryExecution の Query から 1 部目のカタログを落とす（本物どおり）を本物で測る

## 出どころ

- issue #271。#266 の先行実測（2026-09-27、`tools/measure/unquoted-ddl.sh` の ROUND=14、生データ
  `$HOME/athena-unquoted-ddl-measurements/run-20260926-223637`）の範囲外の発見が根拠。記録はブランチ
  `main-measure-266`（ローカルのみ）の `.claude/issue-notes/266.md` の「実測の結果」「範囲外の発見」の 3
- 本物の振る舞い（実測済み）: 開始できた Hive の `CREATE EXTERNAL TABLE <3 部の名前> (n int) LOCATION '..'` は、
  GetQueryExecution の `Query` から 1 部目のカタログと直後の `.` が落ちた。返った `QueryExecutionContext` は
  送ったまま。どれも SUCCEEDED、DDL / CREATE_TABLE、結果は `.txt`

  | ID | 文 | Context | 返った Query |
  |---|---|---|---|
  | z0 | `CREATE EXTERNAL TABLE AwsDataCatalog.<db>.<t> ...` | `Catalog=AwsDataCatalog,Database=<db>` | `CREATE EXTERNAL TABLE <db>.<t> ...` |
  | z0c | `CREATE EXTERNAL TABLE awsdatacatalog.<db>.<t> ...` | 同上 | `CREATE EXTERNAL TABLE <db>.<t> ...` |
  | z0b | `CREATE EXTERNAL TABLE <db>.<t> ...`（対照） | 同上 | 送ったまま |
  | z2 | `CREATE EXTERNAL TABLE <GLUE>.<db>.<t> ...` | `Catalog=<GLUE>,Database=<db>`（自分のアカウントの Glue を指す GLUE 型のデータカタログ） | `CREATE EXTERNAL TABLE <db>.<t> ...` |
  | z3 | `CREATE EXTERNAL TABLE AwsDataCatalog.<db>.<t> ...` | 同上 | `CREATE EXTERNAL TABLE <db>.<t> ...` |
  | z4 | `CREATE EXTERNAL TABLE <t> ...`（対照） | 同上 | 送ったまま |

  #242 の実測では、CTAS（m35）・`CREATE VIEW`（m36）は `awsdatacatalog.` を落とさなかった。Hive の DDL である
  `CREATE EXTERNAL TABLE` は落とす側に入る
- 今の athena-local: `src/operation/reported_query.rs` の `CATALOG_DROPPED` に `CREATE EXTERNAL TABLE` が無いので、
  Store の `Query` は受け取ったまま。本物と `Query` が食い違う
- 気をつけること:
  - Store の `Query` は受け取ったままにするのが CLAUDE.md の不変条件で、例外は #240（前後の空白と `;`）と
    #242（DESCRIBE などの修飾を落とす書き換え）だけ。ここに足すなら、CLAUDE.md の一覧、
    `docs/configuration.md` の "not rewritten" の約束、`docs/dev/decisions.md` も直す
  - `drop_catalog` は Context が AwsDataCatalog か省略のときだけ落とす（#242 で測ったのがそれだけのため）。
    本物は別カタログの Context でも落とした（z2・z3）。athena-local で別カタログの Context に当たるのは
    `TRINO_CATALOG_MAP` の別名
  - 既定の Context で、実在する別カタログを 1 部目にした `CREATE EXTERNAL TABLE` は開始時に
    `Unsupported ddl with 2 catalogs` になる（x3・z1。#266 の範囲）ので、落とすのは開始できる形だけ
- issue 本文が挙げた「測っていない形」（このラウンドで測る）:
  1. 返った Context の Database。#242 の DESCRIBE などは修飾の DB に変わった（m2・m22）。#266 は Context の
     Database と文の DB が同じ形しか測っていない（DB が違う形・Context に Database が無い形）
  2. `CREATE EXTERNAL TABLE IF NOT EXISTS`・列リストの後ろの句（PARTITIONED BY・ROW FORMAT・STORED AS・
     TBLPROPERTIES）付き・`awsdatacatalog . <db> . <t>`（空白入り）・コメント入り
  3. EXTERNAL の無い Iceberg の `CREATE TABLE awsdatacatalog.<db>.<t> (..) LOCATION '..' TBLPROPERTIES
     ('table_type'='ICEBERG')`
  4. Context の Catalog を省略した形
  5. FAILED になる `CREATE EXTERNAL TABLE`（DB が無いなど）の Query
  6. Hive の DDL のほかの文（`CREATE DATABASE`・`ALTER DATABASE`・`SHOW PARTITIONS` など）。
     MSCK REPAIR TABLE は #257 で落ちると分かっている

読み取れる規則（#271 の実装の材料。解釈を含む）:

- `CREATE [EXTERNAL] TABLE [IF NOT EXISTS] <カタログ>.<db>.<t> ...`（CTAS でない形）は、EXTERNAL・句・綴り・空白・名前の前のコメントによらず、
  **成功でも失敗でも** Query から 1 部目のカタログと直後の `.`（前後の空白を含む）が落ちる。カタログは `awsdatacatalog` の綴りによらず、
  別カタログ（`<GLUE>`）の Context では `<GLUE>` も `AwsDataCatalog` も落ちる。S3 Tables の Context の `CREATE TABLE AwsDataCatalog.<ns>.<t>` も
  同じ（過去の生データ 8 件）
- Context の Database は、**3 部の名前（カタログ付き）のときだけ**修飾の DB に変わる（q1・q2・q5b・q13・q24・q25）。2 部の名前（q3・q13b）では
  変わらない。#242 の DESCRIBE は 2 部でも変わった（m2）ので、CREATE TABLE とは規則が違う
- Hive のほかの DDL も落ちる: `SHOW PARTITIONS`（3 部）、`CREATE DATABASE`・`ALTER DATABASE`・`DROP DATABASE`（`awsdatacatalog.<db>` の 2 部）、
  `ALTER TABLE ... ADD PARTITION`（#242 の ALTER TABLE と同じ）。Context の Database が変わったのは ALTER DATABASE だけ（CREATE・DROP DATABASE は変わらない）
- CTAS・CREATE VIEW・SELECT は #242 で送ったまま（落ちない）と分かっている。今回は測っていない
