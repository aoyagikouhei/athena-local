## 設計判断
- D1（Step 4、ユーザー）: Hive 表・ビューの後半（`Detailed Table Information`・`# Detailed Table Information`・`# Storage Information`・`# View Information`）と Iceberg の FORMATTED の後半は、見出しと行の形を本物どおりに作り、Trino から取れる値と実測で定数だった値だけを入れ、取れない値の行は省く（caveats に書く）。推測で埋めない
- D2（Step 4、ユーザー）: 列指定・PARTITION 指定もこの issue に含める
- D3（統括役）: 受け取った文は Trino に送らず、`DESCRIBE <名前>` と追加の問い合わせ（`SHOW CREATE TABLE`・`"<t>$properties"`・`"<t>$partitions"`）を**別のクエリとして**投げ、行を組み立てる。`execution.query` は書き換えない（CLAUDE.md「別のクエリを投げるで足りるなら書き換えない」。前例は #173 の Iceberg の `# Partition spec:`、`completion.rs:13-34`）。CLAUDE.md の「1 文字も違わない」の一覧と `docs/configuration.md` の "not rewritten" に、受け取った文を送らない文として足す
- D4（統括役）: 文の種類・結果ファイル・Content-Type・`.metadata` の先頭の ID・UpdateCount は先頭語だけで決まり、実測と一致するので触らない（`classification.rs:47`、`results.rs:47-68`、`content_type.rs:59-81`、`table_format.rs:191`）。**例外（計画攻撃 A2）**: EXTENDED／FORMATTED のビューは本物が DESCRIBE_TABLE・application・UpdateCount 無し（e_v・f_v）なので、`format_probe` は `execution.describe` に修飾子があるとき、ビューに `DescribeView` と `DESC_VIEW` を付けない
- D5（統括役）: 新しい振る舞いに入るのは、測った形の文だけ（名前のある `DESCRIBE|DESC EXTENDED|FORMATTED <名前>`、その後ろの列 1 つか `PARTITION (...)`、Hive 表・ビュー・Iceberg 表）。名前無し（z1・z2）は今どおり entity_check の Entity Not Found。測っていない組（ビューへの列指定・PARTITION 指定など）は今どおり（構文チェックで 400）。組の表は計画のマトリクス
- D7（統括役、D1 の当てはめ）: 後半の節に入れるのは、(a) Trino から出せる値（DB・表名・列・型・コメント・パーティション列・表かビューか。Iceberg は `SHOW CREATE TABLE` の location・format と `$properties` の `write.format.default`）と、(b) 実測した h・hp・v（Iceberg は i だけ）のどれでも同じだった値。作り方で変わる値（owner・createTime・numBuckets・SerDe などのクラス名・parameters のキーの集合・skewedInfo）と取れない値（Hive の location・ビューの base64）は、行ごと（Thrift なら `key:value` の対ごと）省く。Hive の Table Parameters は、キーの集合が作り方で変わり Trino の `$properties` の綴り（`numfiles`）も本物（`numFiles`）と違うので節ごと省く。PARTITION 指定の Partition Parameters も同じ理由で節ごと省く（計画攻撃の観点 3 の補足）。`Table Type` は表なら `EXTERNAL_TABLE`、ビューなら `VIRTUAL_VIEW`（測った Hive 表は 2 つとも EXTERNAL_TABLE）
- D8（統括役）: 失敗はすべて開始時に決め、既存の `ImmediateFailure` で返す（本物も開始してから FAILED。#244・#257・#273 と同じ形）。無い表と無い DB は probe（`entity_check::probe`）と名前空間の問い合わせ（`table_format::schema_probe_sql`）で分ける。無い列は `DESCRIBE <名前>` の行、無いパーティションは `"<t>$partitions"` で判定する。Iceberg の失敗は `writes_result_file: false`、Hive の失敗は `true`。これで実行後に成功を失敗へ落とす段は要らない（Plan の案 12-2 は採らない）
- D9（統括役）: 測っていない組は今どおり（開始時の判定が「対象外」を返し、構文チェックで 400）。Query の空白は、測った `DESCRIBE␣␣EXTENDED`／`FORMATTED`（キーワードの間のちょうど空白 2 つ）だけを 1 つにし、空白 3 つ以上・タブ・名前の前後は受け取ったまま（未測定。unmeasured に載せる）。`comment_parse_error::detect` が拾うブロックコメント入りの DESCRIBE（de1 など）は新しい経路に入れない（ビュー・無い表の de1 は本物が ParseException。#276 の担当）。Context の Catalog が AwsDataCatalog（大文字小文字によらない）でも省略でもないとき（S3 Tables など。測っていない）も新しい経路に入れない
- D6（統括役）: フェーズの切り方は、配線の前に純関数（認識・Query の表示・行の組み立て）を置き、配線したフェーズで初めて新しい振る舞いに入る。途中のフェーズで成功する形を誤った行で返す状態を作らない（Plan の「失敗系だけ先に配線」案は、開始時に成否を知るための問い合わせが増えるので採らない）

### 開始時と実行時の流れ（フェーズ 3・4）
1. `start_checks::decide` で、`pre_syntax_check_failure` の後・構文チェックの前に `describe_extended::start(app, &query, catalog, database)` を呼ぶ。返り値は `Start::NotApplicable`（今どおり）／`Start::Fail(ImmediateFailure)`／`Start::Run(Describe)`
2. `start` の中: 文を認識（名前が無ければ NotApplicable＝z1・z2 は今どおり entity_check の Entity Not Found）→ DB と `awsdatacatalog.` を落とした文と修飾の DB（`reported_query` を EXTENDED／FORMATTED を読み飛ばせるよう広げる）→ `context_catalog::resolve` と `entity_check::probe` で表の種類 → マトリクスで Fail／Run／NotApplicable を決める（Missing は `schema_probe_sql` で DB の有無を見て文言を選ぶ。列指定は `DESCRIBE <名前>` の行、PARTITION 指定は `$partitions` を開始時に引く）
3. Fail・Run のときは構文チェックと entity_check・quoted_names・unquoted_ddl・comment_parse_error の判定を飛ばし、`Execution` に Query（落とした文、空白 2 つを畳んだもの）と Database（修飾の DB）を入れる。Run は `Execution.describe: Option<Describe>`（修飾子・列／パーティション・名前の文字列）を持たせる（`Submission`・`Decision` にも同じ形で通す）
4. `background_execution::run` で `execution.describe` が Some なら、Trino に `DESCRIBE <名前>`（別名を当てる）を送り、Iceberg は `SHOW CREATE TABLE`（既存の `iceberg_partition_specs` を広げる）と `$properties` を追加で引き、`describe_detail` で行を組んで `utility_rows::reshape` の代わりに返す。`format_probe` の形式は `target_table` の読み方の修正（A1）で正しい表を引き、FormatOverride・UpdateCount・Content-Type は今のまま（D4。ビューの例外 A2 だけ）。実行時に失敗を作る段は置かない（D8）
5. `target_table::parse_target_table`: DESCRIBE の候補を `DESCRIBE EXTENDED`・`DESCRIBE FORMATTED`・`DESC EXTENDED`・`DESC FORMATTED`・`DESCRIBE`・`DESC` の順にし、`find_map` で**名前まで読めた**候補を採る。名前無しの `DESCRIBE EXTENDED` は前の 4 つで名前が読めず `DESCRIBE` に落ち、今どおり `EXTENDED` を名前と読む（z1・z2 を壊さない）。`extended.t` のような名前も `DESCRIBE` の候補に落ちる

### 手元の Trino での到達性（統括役、待ちの間の確認。compose の trino、2026-09-27）
一時的なスキーマに Hive 表（列コメント付き）・パーティション付き Hive 表（1 行）・パーティション付き Iceberg 表を作って投げ、最後に消した。

- 本物の EXTENDED／FORMATTED の行をこれらから組めるかは、実測の結果と突き合わせて実装側で決める
