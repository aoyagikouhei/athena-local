## 実測の手順
- スクリプトのパス: `tools/measure/describe-extended.sh`（新規作成）
- 実行例（`tools/dev.sh` 経由。DB を省略するか実在しなければ SHOW DATABASES の候補の 1 件目を自動で使う）:
  ```
  tools/dev.sh OUTPUT=s3://your-bucket/prefix/ DB=your_db bash tools/measure/describe-extended.sh
  ```
  資格情報はホストのシェルで `AWS_ACCESS_KEY_ID` などを export してから（または `~/.aws/credentials`）。
- 必須の環境変数: `OUTPUT`（`s3://bucket/prefix/` の形、末尾に `/`）。
- 任意の環境変数: `DB`・`CATALOG`（既定 AwsDataCatalog）・`REGION`（既定 ap-northeast-1）・`OUT_DIR`・`POLL_TIMEOUT`・`RETRY_MAX`・`RETRY_DELAY`（スクリプト先頭のコメントに詳細）。
- 出力先: `${DEV_HOST_HOME:-$HOME}/athena-describe-extended-measurements/run-<日時>/`（リポジトリの外）。`summary.txt` が実名をマスクした、そのまま貼れる一覧。
- 呼び出し回数（StartQueryExecution のみ。GetQueryExecution・GetQueryResults・S3 は含めない）: 全部成功する場合の見込みは 60 回（preflight の SHOW TABLES 1 回 + フィクスチャ 7 回〔CREATE 4・SHOW CREATE TABLE での形式裏取り 3〕+ 項目 48 回 + 後始末の DROP 4 回。DB の自動選択で SHOW DATABASES が要れば +1）。ドライラン（PATH に置いた偽 `aws`。HP フィクスチャの作成をわざと実行時 FAILED にして skip 伝播を確かめる構成）での実測値は 53 回（HP に依存する 6 項目〔e_hp・f_hp・d_hp・p3・p4・z5〕が未測定になり、verify-hp・drop-hp も呼ばれないため 60 から 7 少ない。加えて対照の d_v だけ初回を一時的な失敗にして retry_aws の再試行を確かめたため +1 され、53）。
- 課金と DDL: あり。フィクスチャ 4 つを作る: `athena_local_probe_275_h`（Hive の EXTERNAL TABLE。列 `n int`、`s string`（列コメント付き））・`athena_local_probe_275_hp`（Hive。CTAS で `partitioned_by`、最小の 1 行 `p='x'`）・`athena_local_probe_275_i`（Iceberg。CTAS で `partitioning`、最小の 1 行 `p='x'`）・`athena_local_probe_275_v`（ビュー）。投げる項目はすべて `DESCRIBE` 系の読み取りのみ（`ALTER`・`RENAME`・`DROP COLUMN` は投げない）。最後に 4 つとも `DROP`。場所は `OUTPUT` の下の実行ごとの `tables-probe-275-*-<日時>/`（Hive の CTAS は DROP してもデータ 1 行が残り、同じ場所では 2 回目の作成が失敗するため。統括役の受け入れ判定で直した）。スキャンする `SELECT` は投げない（CTAS の `SELECT` はリテラルだけ）。

### 読み直し（過去の生データ。統括役が読み直した既知の事実）

- `$HOME/athena-quoted-names-measurements/run-20260925-083528/u6-extended-u.*`・`u6-extended-q.*`・`u6-formatted-q.*`（issue #204）: 無引用の `DESCRIBE EXTENDED <t>` は SUCCEEDED（UTILITY/DESCRIBE_TABLE）。`u6-extended-q`・`u6-formatted-q`（`DESCRIBE EXTENDED "t"`・`DESCRIBE FORMATTED "t"`。引用符付き）は開始時に `mismatched input '"<TT>"'. ### 手元の Trino での到達性（統括役、待ちの間の確認。compose の trino、2026-09-27）
一時的なスキーマに Hive 表（列コメント付き）・パーティション付き Hive 表（1 行）・パーティション付き Iceberg 表を作って投げ、最後に消した。
- `DESCRIBE EXTENDED hive.<s>.<t>` → `line 1:19: mismatched input 'hive'. Expecting: '.', <EOF>`（Trino に構文が無い。`EXTENDED` を表の名前として読む）
- `DESCRIBE hive.<s>.<t> n`（列指定）→ `line 1:26: mismatched input 'n'. Expecting: '.', <EOF>`（Trino に構文が無い）
- `DESCRIBE`・`SHOW COLUMNS FROM` → 列 `Column`・`Type`・`Extra`・`Comment` の 4 列。列コメントは `Comment` に、Hive のパーティション列は `Extra` が `partition key`。Iceberg のパーティション列は `Extra` が空
- `SELECT * FROM "<t>$properties"` → Hive は列ごとのプロパティ（`auto.purge`・`numfiles`・`numrows`・`totalsize`・`transactional`・`trino_query_id`・`trino_version` など）の 1 行、Iceberg は `key`・`value` の行（`format`・`provider`・`current-snapshot-id`・`location`・`format-version`・`write.format.default`）
- `SELECT * FROM "<t>$partitions"` → Hive はパーティション列の値の行、Iceberg は `partition`・`record_count`・`file_count`・`total_size`・`data`
- `SHOW CREATE TABLE` → Trino の書式（`WITH (format = 'ORC', partitioned_by = ARRAY['p'])`）で、Hive の DDL の書式ではない
- 本物の EXTENDED／FORMATTED の行をこれらから組めるかは、実測の結果と突き合わせて実装側で決める

## 実測の経緯
- 2026-09-27: request-measurement（先行実測、issue ごとに分けて古い順に流す運用）で `tools/measure/block-comment-parse-error.sh`・`tools/measure/unquoted-ddl.sh` を手本に `tools/measure/describe-extended.sh` を新規作成。フィクスチャに H（Hive、列コメント付き）・HP（パーティション付き Hive、CTAS）・I（Iceberg、CTAS）・V（ビュー）を追加し、EXTENDED・FORMATTED・対照の DESCRIBE（14 項目）、Query の書き方の変異（20 項目）、列・パーティション指定（9 項目）、失敗系（5 項目）の計 48 項目と、GetQueryResults の全ページ採取（ColumnInfo・Rows・UpdateCount）を実装した。
- ドライラン: PATH に置いた偽 `aws`（Python 製。SQL の内容で SUCCEEDED/FAILED/START_FAILED を判定し、GetQueryExecution・GetQueryResults・S3 の応答を状態ファイルから組み立てる）で `bash -n` とあわせて確認。確認できたこと: 48 項目 + フィクスチャ + 後始末が全部走ること、呼び出し回数が summary 冒頭の数と一致すること（53）、HP フィクスチャの作成失敗で 6 項目が正しく skip されること、対照 d_v の一時的な失敗（`Could not connect to the endpoint URL`）が 1 回の再試行の後 SUCCEEDED になり `attempts=2` が記録されること、DB 名・バケット名・アカウント ID・IAM ARN が summary.txt のどのブロック（Query・Context・ColumnInfo・GetQueryResults の行・結果ファイル本体・StateChangeReason/AthenaError）にも漏れないこと、SIGINT による中断で trap が 4 つの DROP を送ること、`.tmp-*` が中断後に残らないこと。途中で `GetQueryResults` の `ResultSetMetadata: null`（FAILED 時。docs/dev/measurements/result-files.md に実測記録あり）を辛うじて `.get(key, {})` で拾えず落ちるバグ（Python の `dict.get(key, default)` はキーが存在して値が `None` のときは `default` を使わない）を見つけて `results_columns_of`・`results_rows_of`・`read_execution_fields` を `(d.get(key) or {})` の形に直した。shellcheck はこの環境・toolbox のどちらにも入っておらず未実行（`bash -n` とドライランで代替。#257 と同じ）。
- 2026-09-27: 統括役の受け入れ判定で、フィクスチャの場所を実行ごと（`tables-probe-275-*-<日時>/`）に分けた（Hive の CTAS は DROP してもデータが残り、再実行で作成が失敗するため）。本物への呼び出し回数・DDL・秘密の扱いは確認済み。
