### 実測で決まった規則（2026-09-23、`.claude/issue-notes/70-measure-content-type.sh`、36 項目）

| 対象 | binary/octet-stream | application/octet-stream |
|---|---|---|

- binary の項目はどれも `QueryPlanningTimeInMillis` が Statistics に無く、application の項目には必ずある（`DESCRIBE`・`SHOW CREATE TABLE` は例外で、計画時間なしの application）。本物は定数だけの SELECT と SHOW 系（`SHOW CREATE TABLE` を除く）をエンジンの計画を通さずに書いていると読める。
- サイズは 300 万行・28.9 MB まで単一 PUT の application。マルチパート（binary）になる境界は未測定。140 MB の例はテーブルのフルスキャンで、定数生成の 28.9 MB は単一 PUT だった。
- 2026-09-17 の「`.csv` は application（6 件中 5 件）」は、少数派の 1 件が `SELECT 1` で、多数決で丸めていた。`.txt` の「binary と application に割れていたので多数派を採る」（2026-09-16）も同じ。

### 現行コードとのずれ

- `src/results.rs:86` `ResultFile::content_type`: `Csv | Metadata | FailedText → application`、`Text | Manifest | Table → binary`。
  - `.txt`: `DESCRIBE`・`EXPLAIN`・`SHOW CREATE TABLE` を binary で送っている（本物は application）
  - `.metadata`: SHOW 系を application で送っている（本物は binary）
  - `.csv`: リテラルだけの SELECT を application で送っている（本物は binary）
- `ResultLocation::metadata`（`src/results.rs:133`）は `file: ResultFile::Metadata` の固定値なので、`.metadata` の Content-Type を本体に追従させるには `ResultLocation` に Content-Type を持たせるか、`Metadata` に親の種別を持たせる変更が要る。
- 上書きの経路は `src/operation/result_output.rs:60`（DROP TABLE × Iceberg などの `ENGINE_DDL_CONTENT_TYPE`）の 1 か所だけ。

### 共有できる既存機構

- 先頭キーワードの判定は `ResultFile::of`（`src/results.rs`）と `classification.rs` の `statement_type`／`substatement_type` の 2 か所にあり、どちらも `catalog::skip_leading_trivia` でコメントを読み飛ばし、`words` で大文字化した単語列を見る。`SHOW CREATE TABLE` の例外は `substatement_type` が既に `SHOW_CREATE_TABLE` として区別している。
