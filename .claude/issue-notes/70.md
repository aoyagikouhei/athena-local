## 設計判断

1. **判定の置き場所**: 新モジュール `src/content_type.rs` に「ファイルの種類 × SQL → Content-Type」を集約する。`ResultFile::content_type`（多数決の固定値）は削除。理由: `ResultFile::of` は「文の種類だけで決まり、SQL の残りは見ない」（`results.rs:44`）をファイル名の判定として守り、SQL の残りを見る判定を別関数に置く。`results.rs` は 696 行で足せない。
2. **`.metadata` を本体に追従させる**: `ResultLocation` に `content_type: &'static str` を持たせ、`new` で SQL から決める。`metadata()` はそれを引き継ぎ、`failed()` は application 固定。`put` の上書き引数（`Option<&str>`）は残し、engine DDL（#39）は本体と `.metadata` の両方に同じ上書きを渡す（`write_metadata` に引数を足す）。
3. **リテラルだけの SELECT の文法は実測した形だけ**: `SELECT` の後に、リテラル（符号なし整数・`.` 付き小数・`'...'`・`TRUE`/`FALSE`）に任意で `AS <無引用の識別子>` が付いたものを `,` で並べ、その後ろが空白とコメントだけで終わるもの。一般化は 2 点だけ（複数列と別名の組み合わせ `SELECT 1 AS i, 2 AS j`、キーワードの大文字小文字）。**それ以外の形（`SELECT -1`、`SELECT 1;`、`SELECT 1 LIMIT 1`、`SELECT DATE '...'`、`SELECT 1.5E0`、`SELECT 'a' || 'b'`、`SELECT ARRAY[1]`、`SELECT 1 AS "x"`、裸の別名 `SELECT 1 i`、`(SELECT 1)`、`VALUES 1`）は application に落とす**（＝これまでの値。本物が binary にする形を取りこぼす方向にだけ外れる）。README に「測った形」と「測っていない形」を書く。→ 6b で確認
4. **`.txt` の判定は先頭の語**: `DESCRIBE`/`DESC`、`EXPLAIN`、`SHOW CREATE` → application、それ以外の `.txt`（`SHOW` 系・DDL）→ binary。`DESC` と `SHOW CREATE VIEW` は未測定だが、既存の `metadata_query_id`（`result_output.rs:159`）が同じ組で判定しているのでそれに揃える。→ 6b で確認だけ
5. **`Manifest`／`Table` は application**。本体は書かないが `.metadata` は `metadata()` 経由で置く（`result_output.rs:75` → `:142`。INSERT は `rows bigint` の列がある）ので、`.metadata` の実値になる。本物の INSERT・CTAS の `.metadata` は application（2026-09-17／18 実測）。計画レビューの high で「到達しない」を覆した。`FailedText` は application のまま（変更なし）。
6. **`src/results.rs` の分割は範囲外**（`mod tests` が 58%）。起票する（範囲外の発見）。

### 変更内容と根拠

- `content_type::of(file, query)`:
  - `Csv` → `is_literal_only_select(query)` なら binary、でなければ application（実測の結果の表）
  - `Text` → `text_content_type(query)`: `catalog::words(query)` の先頭 2 語で `("DESCRIBE" | "DESC", _) | ("EXPLAIN", _) | ("SHOW", "CREATE")` → application、それ以外 binary（実測の結果の表。組は `result_output.rs:159` と同じ）
  - `Manifest | Table` → application（`.metadata` の実値。本体は書かない）。`Metadata | FailedText` → `unreachable!`（`path` と同じ扱い。キーは `ResultLocation` が作る）
  - `text_content_type` の match の上に「`result_output.rs:159` の `metadata_query_id` と同じ組。片方を変えたら両方」のコメント（計画レビュー low）
  - `write_result` の `content_type`（engine DDL の上書き）は `if should_write` の外に出して `write_metadata` にも渡す（計画レビューの確認事項）
- `is_literal_only_select(query)`（バイト位置を持ち回る）:
  1. `catalog::skip_keyword(query, "SELECT")` で先頭トリビアと `SELECT` を飛ばす（無ければ false）
  2. 繰り返し: トリビアを飛ばす（`skip_leading_trivia`）→ リテラルを 1 つ読む（先頭が数字なら `[0-9]+` に任意で `.[0-9]+`、`'` なら `catalog::skip_quoted`、それ以外は `skip_keyword(_, "TRUE")` か `"FALSE"`。どれでもなければ false）→ トリビア → `skip_keyword(_, "AS")` が付けば識別子 `[A-Za-z_][A-Za-z0-9_]*` を 1 つ読む（無ければ false）→ トリビア → 次が `,` なら飛ばして繰り返し、空なら true、それ以外は false
  3. 数字の直後に識別子文字が続く（`1e0`、`1abc`）と、`.` の後に数字が無い（`1.`）は false
- 引用符 → コメントの順（design-checklist #52）: リテラルは `skip_quoted` で読むので、`'--'` の中の `--` をコメントと読まない
- `ResultLocation::new` は `file = ResultFile::of(query)`、`content_type = content_type::of(file, query)` を保持。`metadata()` は `content_type` をコピー、`failed()` は `FAILED_CONTENT_TYPE`（application）

### 直列化・エスケープ境界／表現の正規化境界
