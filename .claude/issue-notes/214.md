# #214 QueryExecutionContext の Catalog が実在しないとき、本物は既定のカタログで解決して成功するが athena-local は Trino で失敗する

- ベースブランチ: main ／ ブランチ: main-214 ／ 着手前 SHA: 866b003

## 事前に確認した事実
Explore 3 本（A: 実行経路、B: 記録と判断、C: テストの足場）から転記。

- **既定の当て方**: `context_defaults`（src/operation/execution.rs:180-198）は Catalog/Database に既定を当てず、受け取った値のまま Store と Fingerprint に入れる（#167）。既定（`TRINO_CATALOG`=`config.default_catalog`）は `run()`（execution.rs:273-294）で `execution.catalog.or(default_catalog)` として当て、`config.trino_catalog`（config.rs:94-99、`TRINO_CATALOG_MAP` の別名の解決）を通して Trino に送る。**`default_catalog` は Context の省略時だけ効く**（`.or`）。[A1,A3]
- **Trino への送り方**: `X-Trino-Catalog`/`X-Trino-Schema`（src/trino.rs:106-126）。実在しない名前もそのまま載る。[A3]
- **同じカタログを使う経路**（run() の中）: パラメータ分類の probe（execution.rs:298-303）、本体の execute（309-314）、Iceberg のパーティション行（completion.rs:26、327）、`format_probe::probe_target_format`（format_probe.rs:41-58。別名解決前の `raw_catalog` を受け取る）。開始時は `entity_check::check`（entity_check.rs:41 で既定を当て、53 で別名解決＋小文字化）。[A4]
- **カタログの有無を知る手段**: 汎用の問い合わせは無い。`table_format::probe_sql`（table_format.rs:119-126）が `system.metadata.catalogs` を 1 カタログ名で引くだけ（対象の表がある文でしか呼ばれない）。[A7]
- **Trino の「カタログが無い」エラー**は `failure.rs` の `measured_error_type` に無く、汎用の USER/1000 に落ちる（failure.rs:35-43,66-83）。[A5]
- **GetQueryExecution の Catalog** は保存した生の値を小文字にして返す（query_execution.rs:177-185、#157）。本物も実在しない名前を小文字で返すので、ここは変えない。Fingerprint は生の値（store.rs:97-107、#150）。[A2]
- **decisions.md:97（#207）**: 「既定・文脈のカタログが Trino に無いときは未実測なので、存在の確認では判定せず今までどおり実行する」→ #212 の Y3 で実測が埋まった。[B2]
- **実測の既存分**: #157（client-request-token.md:132-156）で実在しない Catalog でも `SELECT 1` は SUCCEEDED、名前の解決は Catalog も大文字小文字を区別しない。#212 Y3（statements.md 末尾）で `DESCRIBE`・`SHOW COLUMNS` も SUCCEEDED、実在しない表は Entity Not Found。**表を読む SELECT・SHOW TABLES・DDL・INSERT・エラーの文言は未実測**。[B1]
- **約束との関係**: 「SQL の本文は書き換えない」「TRINO_CATALOG_MAP の置換の条件は広げない」（CLAUDE.md:75、decisions.md:73-74）は SQL 本文の話で、Context のカタログ（ヘッダ）の差し替えは対象外。ただし `docs/configuration.md:10` の `TRINO_CATALOG` の説明（Context が無いときの既定）の意味は変わる。[B7,B 最後]
- **テストの足場**: 偽 Trino は SQL 文字列だけで応答を振り分け、`X-Trino-Catalog` では振り分けない（tests/common/mod.rs:520-524）。`trino_requests()` で届いたヘッダを検査できる。近い前例は tests/catalog.rs:100-116（省略時に既定を送る）と :118-151（別名に無い名前はそのまま送る）。`probe_response`（tests/entity_check.rs:31-39）で probe の応答を作れる。[C1,C2,C4]
- **実機の足場**: `tools/measure/unmeasured-batch/`（`TARGET=local` で compose の Trino＋athena-local に aws CLI で投げる。lib-local.sh:87-124）。compose の実在カタログは hive・iceberg・memory。[C5]
- 落とした番号: A6（catalog.rs は Context のカタログと無関係）、A8 のうち上に書いたもの以外、B3〜B6（unmeasured・docs の文面は docs の更新で使う）、B8・C6（手順の要約）。

## 設計判断
- D1（ユーザーの判断、Step 4）: Context の Catalog が Trino に実在しないときは、**`TRINO_CATALOG_MAP` の `AwsDataCatalog` の別名**に差し替える。別名が無ければ `TRINO_CATALOG`、それも無ければ今までどおりそのまま送る。理由: 本物の既定は AwsDataCatalog なので、その名前に忠実にする（推奨の「TRINO_CATALOG に差し替える」ではなくこちらを選んだ）。
- D2（ユーザーの判断、Step 4）: 「実在しない」は**実行前に Trino に問い合わせて**見分ける（`system.metadata.catalogs`。Context に Catalog があり、`TRINO_CATALOG_MAP` の別名でもないときだけ）。問い合わせが失敗したら今までどおりに倒す。
