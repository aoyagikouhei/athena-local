### compose の挙動（Explore 3: 実測。Engine 29.8.1、compose v5.5.1）
- `run --rm --use-aliases dev` で別名 `dev` が付き他コンテナから引ける。無しだと引けない（コンテナ名なら可）。`dev` が 2 つ同時にあると DNS は両方の A を返し順序が入れ替わる（接続先が不定）。
- dev の中から `compose -f <abs> up -d minio` は dev を作り直さず（oneoff は対象外）、後から上がった minio に `minio:9000` で届く。
- **`down -v <サービス名>` はそのサービスだけ落とし、その named / anonymous volume だけ消す。dev は残る**（ネットワークは使用中で残るが exit 0）。`down`（サービス名無し、`--remove-orphans` 無し）も oneoff の dev は残す。**`down --remove-orphans` は dev 自身を殺し、後始末が途中で止まる**（exec が 137）。
- anonymous volume を `up -d --force-recreate -V` で作り直すと古いものがラベル無しでリークする。**毎回空にするなら named volume + `down -v <svc>` → `up -d <svc>`**。
- `depends_on` は `run` でも起動される（`--no-deps` で止まる）。`condition: service_healthy` も効く。dev に depends_on は付けない。
- Trino 482 のイメージは healthcheck 内蔵（`/usr/lib/trino/bin/health-check`、10s）。MinIO は無し（compose 側の curl が要る）。`up -d --wait` は healthy を待つ（Trino は約 10 秒）。`--wait-timeout` 超過は exit 1 でコンテナは残る。
- `TRINO_TAG=999999 up -d --pull never --force-recreate trino` は `No such image` で exit 1（補間は効く）。
- dev で `0.0.0.0:8087` に bind すれば nginx（`proxy_pass http://dev:8087`）から 200。`127.0.0.1` だと 502。**`dev` が無い状態で nginx を起動すると `host not found in upstream "dev"` で落ちる**。nginx は起動時に一度だけ引くので、dev を作り直すと古い IP を掴む → `resolver 127.0.0.11` + 変数の proxy_pass（知識）。
- `-f <abs>` なら cwd に関係なく相対パスは compose ファイルの場所基準（`--project-directory` 不要）。`.env` も compose の場所基準。
- ports 無しの人間の入口: `docker compose exec trino trino --execute 'SELECT 1'`（実測可）、`tools/dev.sh curl http://trino:8080/...`。

## 設計判断

Step 4 でユーザーに確認済み（2026-09-23）:
1. **この issue で dev を compose のネットワークに入れ（`network_mode: host` を外す）、足場 9 本を全部移し、古い compose 6 本を消す。** #129 には tools/measure の aws 系・awscli・mc・CLAUDE.md の cargo コマンドの判断だけ残す。理由: 足場が `trino:8080` で相手を見るには dev が同じネットワークに要る。移行中に「移行済みの足場は dev から届かない」状態を作らない。副作用: 足場を 2 つ同時に走らせられない（README に書く）。
2. **付属物（カタログ 3 つ、tls の nginx.conf と make-cert.sh、jdbc-client）は `tools/compose/{catalog,tls,jdbc-client}` に移す。** trino-probe の `catalog/`（minio/catalog と同一）は消し、`catalog-legacy/` と `catalog-nofsflag/` は trino-probe に残す。

統括役の仮決め（Plan と計画レビューで反証されなければ確定）:
3. **状態の分離は「足場ごとに該当サービスを `down -v <svc...>` → `up -d <svc...>` で作り直す」で保つ**（データは named volume）。理由: 4 つの足場（sdk-retry、jdbc-show-metadata、jdbc-drivers、trino-probe）は残骸で判定が狂い、anonymous volume の `-V` はリークする。trap は `down -v <svc...>`（KEEP_UP で省略）。サービス名を列挙する理由（Plan の反証で差し替え）: `jdbc-client-m2`（maven のキャッシュ）を消さない、足場が使わないサービスに触れない。`--remove-orphans` は dev 自身を殺すので使わない（サービス名無しの `down` は dev を残すが、使わない）。サービス名無しの `up -d` も禁止（dev まで空の値で作ろうとする）。
4. **`tools/dev.sh` の run に `--use-aliases`** を足し、compose.yml の dev から `network_mode: host` を外す。dev に `depends_on` は付けない。
