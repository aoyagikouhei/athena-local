### 文言の形（`<k>` は書いた綴りのキーワード。小文字なら小文字: s14・s15・r6・a5・d2）
| 位置 | StateChangeReason |
|---|---|
| 先頭のコメント（SHOW CREATE・MSCK・ALTER・DESCRIBE 共通） | `FAILED: ParseException line L:C cannot recognize input near '/' '*' '<x>'`。`<x>` はコメントの中身の最初の字句: `c`・`abc`・`a`（`/* a b */`）・`*`（`/**/`）・`,`（`/* , */`）（s20〜s24） |
| SHOW の後 | `... line L:C cannot recognize input near '<SHOW>' '/' '*' in ddl statement` |
| SHOW CREATE の後 | `... line L:C mismatched input '/' expecting TABLE near '<CREATE>' in show statement` |
| MSCK の後／MSCK REPAIR の後 | `... line L:C missing EOF at '/' near '<MSCK>'`／`near '<REPAIR>'` |
| 名前の直前（SHOW CREATE TABLE・MSCK REPAIR TABLE・ALTER TABLE の後） | `... line L:C cannot recognize input near '/' '*' '<x>' in table name`（s5・r5・a13） |
| ALTER の後 | `... line 1:0 cannot recognize input near '<ALTER>' '/' '*' in alter statement`（位置は ALTER の位置。空白 2 つ・改行でも 1:0: a6・a7） |
| DESCRIBE・DESC の後 | `... line 1:0 cannot recognize input near '<DESCRIBE>' '/' '*' in describe statement`（d3 は `'DESC'`） |

- 位置 `L:C`（ALTER・DESCRIBE 以外）: `/` の行（1 始まり）と列（0 始まり）を、**2 文字以上続く空白（空白・タブ・改行）を 1 つの空白に畳んだ文**で数えた値
  （ラウンド 3 で確定）。1 文字の空白はそのまま（`SHOW\n/*` → 2:0、`SHOW\t/*` → 1:5）。畳む例: `SHOW  CREATE /*` → 1:12（p1。「キーワード終端 + 1」なら 13 で外れ）、
  `SHOW\t\t/*` → 1:5（p11）、`SHOW\n\n/*` → 1:5（p6）、`SHOW CREATE\n  /*` → 1:12（p5）、`SHOW  CREATE  TABLE  /*` → 1:18（p8）。先頭の空白は落ちる（p7 → 1:0）
- DROP COLUMN の ErrorMessage の位置も畳んだ文で数える（n9 `ALTER  /* c */ ...` → 1:70。畳まなければ 71）。`'COLUMN'` は書いた綴り（n7 → `'column'`）
- 先頭コメントの `<x>` は Hive の字句（ラウンド 3 で確定）: 英数字と `_` の並び（`c`・`abc`・`1a`・`_a1`。`a.b`・`a-b` → `a`）、数は小数まで（`1`・`1.5`）、
  引用符の文字列は引用符ごと（`'x'`・`"q"`）、それ以外の記号は 1 文字（`,`・`)`・`+`（`/*+ x */`）・`*`（`/**/`））。空白と改行は飛ばす（`/*\nc */` → `c`）。
  非 ASCII は飛ばす（`/* あ */` → 閉じの `*`）。名前の直前の `in table name` の形も同じ字句（c11 `/* 1 */` → `'1'`）
- `/* c */\nSHOW ...` は 1:0（s26）、`-- x\n/* c */ SHOW ...` は 2:0（s25）、コメント 2 つ（`SHOW /* a */ /* b */`）は 1 つと同じ（s27）

## 設計判断
- D1 範囲（ユーザーの判断）: SHOW CREATE TABLE・MSCK REPAIR TABLE・ALTER TABLE（ADD COLUMNS・DROP COLUMN・RENAME TO の 3 動作とも）・
  DESCRIBE／DESC（#242 の欠陥の取り込み: Iceberg 表は成功させる、DESC と先頭コメントも失敗させる）。コメントの位置は「先頭」「キーワードの間」
  「名前の直前（TABLE の後）」。名前の中・名前の後ろ・句の中は測っていないので今までどおり
- D2 MSCK の Iceberg 表（ユーザーの判断）: 2/1200 `Query type not supported by Athena Iceberg at this time`（本体なし）も扱う。
  ラウンド 3 でコメント無しも同じと分かったので、Iceberg 表への MSCK はコメントの有無・位置によらず 2/1200 にする（今は構文チェックで弾いている）。
  ビューへのコメント入りの MSCK は ParseException（コメント無しのビューは 2/1100 の別の失敗で、今までどおり構文エラーのまま。範囲外）
- D3 失敗させる表: SHOW CREATE TABLE・ALTER は Hive 表・無い表・ビュー（Iceberg 表は今までどおり実行）。DESCRIBE は表で Iceberg 以外
  （ビューは成功、無い表は #207 で開始時に弾く）。MSCK は Hive 表・無い表が ParseException、Iceberg 表が 2/1200
- D4 失敗の種類: ParseException は 1/1003・`<id>.txt` に文言・`.metadata` 無し。ALTER の RENAME TO・DROP COLUMN だけ 2/1006 で、
  ErrorMessage が StateChangeReason と別（RENAME は `Query type not supported by DDL engine.`、DROP COLUMN は
  `line 1:<COLUMN の位置 + 1>: mismatched input 'COLUMN' expecting 'PARTITION'`。コメント無しの Hive 表・無い表の過去の実測
  （#39・#204・#208・#43・#217 の生データ）と同じ ErrorMessage で、StateChangeReason だけ ALTER の ParseException に替わる）
- D5 near の語は書いた綴り。位置は `/` の行と列（ALTER・DESCRIBE は 1:0）を、2 文字以上続く空白を 1 つの空白に畳んだ文で数える（ラウンド 3）。
  DROP COLUMN の ErrorMessage の位置も同じ畳んだ文で。先頭コメントの `<x>` は実測の字句の規則（実測の結果の節）。測っていない字句（`<=` などの 2 文字の記号、
  引用符の中のエスケープ）は同じ規則で近似し、unmeasured.md に載せる
- D6 MSCK の分類を本物どおり `DDL`／`MSCK_REPAIR` にする（FAILED にした実行の GetQueryExecution に出るため）
- D7 CLAUDE.md の不変条件: 送る SQL は書き換えない（送らずに失敗させるだけ）
