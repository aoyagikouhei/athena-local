# #273 S3 Tables の Context の名前空間が無い CTAS（Database 省略・残りの形）を本物で測る

## 出どころ

- issue #273（`gh issue view 273 --comments`）。#251 のラウンド 15（`main-measure-251` の
  `.claude/issue-notes/251.md`、生データ `$HOME/athena-unquoted-ddl-measurements/run-20260926-231125`）で
  見つけた事実が根拠
- 本物の振る舞い（実測済み）: S3 Tables の Context の 1 部・2 部の CTAS で、対象の名前空間が無いとき、本物は
  開始して FAILED になる（2 / 1300）。理由は次の 2 文がつながったもの:
  - `NOT_FOUND: Schema <S3 Tables のカタログの内部名>$schema:<名前空間> not found.`
  - ` You may need to manually clean the data at location '<OutputLocation>tables/<id>' before retrying.
    Athena will not delete data in your account.`
  - t16（1 部の名前、Context の Database が無い名前空間）・t17（2 部の名前）の 2 件だけで確認済み。Database を
    省略した Context（`<S3NODB>`）の形、IF NOT EXISTS、名前空間の綴りを大文字にした形、`WITH NO DATA`、
    問い合わせの失敗・無い表との順序、`WITH (format=...)`、バッククォート・二重引用符、Glue にはあるが
    S3 Tables には無い名前、問い合わせ自体は通る形は未測定
- 気をつけること:
  - 「manually clean the data」の注意は、CTAS が実際に一部のデータを書いてから名前空間が無いと気づいて
    FAILED にする（データの置き残しがありうる）ことを示唆する。#251 の r4〜r8c で使った
    `check_ctas_orphan_data`（`aws s3 ls --recursive`、読み取りのみ）でこのラウンドでも置き残しを確かめる
  - Database を完全に省略した Context（`Catalog=<S3TABLES_CATALOG>` だけ）は、これまでのラウンドでは
    測っていない（H・N・R・S・Z・cl/pr/pn/pa/tp 群はすべて Context に Database を指定していた）。この
    ラウンドで新しく使う。受理された場合の後始末は、まず同じ Context（Database 無し）で
    `DROP TABLE IF EXISTS` を試み、それで消えなければ既存の名前空間を Database にした Context で
    もう一度試みる（どちらも失敗すれば要手動削除）
  - c2（`CREATE TABLE <NOPE>.<t> (n int)`。非 CTAS）は #251 で `Cannot find or access the specified table`
    になると分かっている（対照）

## 実測の手順

```
cd /home/aoyagikouhei/git/athena-local/.claude/worktrees/measure-273
tools/dev.sh OUTPUT=s3://your-bucket/prefix/ DB=your_db ROUND=19 \
  S3TABLES_CATALOG=s3tablescatalog/your-bucket S3TABLES_NS=your_ns \
  bash tools/measure/unquoted-ddl.sh
```

**S3TABLES_CATALOG・S3TABLES_NS は必須**（無ければ d・f・c 群はすべて「未測定（S3TABLES_* 未設定）」になり、
準備の実在する表 `<PROBE>_src` 以外ほぼ何も測れない）。

- スクリプトのパス: `tools/measure/unquoted-ddl.sh`（`ROUND=19` を追加。ROUND=1〜14・16・17 の挙動は変えて
  いない。ROUND=15 は issue #251、ROUND=18 は issue #272 がそれぞれ別ブランチ `main-measure-251`・
  `main-measure-272` で使うため、このブランチには無い。17 の次は 19）
- 必須の環境変数: `OUTPUT`・`DB`・`S3TABLES_CATALOG`・`S3TABLES_NS`
- 任意の環境変数: ほかは既存と同じ `CATALOG`・`REGION`・`OUT_DIR`・`POLL_TIMEOUT`・`RETRY_MAX`・`RETRY_DELAY`
  （`FEDERATED_CATALOG`・`CREATE_GLUE_CATALOG` はこのラウンドでは使わない）
- 出力先: `${DEV_HOST_HOME:-$HOME}/athena-unquoted-ddl-measurements/run-<日時>/`
- 本物への呼び出し回数の見込み（StartQueryExecution）: 23（S3TABLES_* あり）／4（無し）。preflight 2 +
  準備（実在する Glue の表 `<DB>.<PROBE>_src` の作成・削除）2 + S3TABLES_* が揃うときだけの d0〜d4 の 5・
  f1〜f12 の 12・c1・c2 の 2（計 19）。d3・c1 は既存の名前空間を指すため受理される見込みで、その場で DROP
  する後始末が 1 本ずつ増える（+2）。d1・d2・d4 が想定に反して受理されれば同様に増え、その DROP が
  `<S3NODB>` で失敗すれば `<S3>` でのもう一度の DROP でさらに増える
- DDL・課金: 実在する表 `<PROBE>_real` は作らない。準備で実在する Glue の表 `<DB>.<PROBE>_src` を 1 つ
  作り（S3TABLES_* によらず）、最後に消す（f10 の問い合わせ元。作れなければ f10 だけ未測定）。d・f・c 群の
  CREATE TABLE は、受理されたらその場で DROP して消す。スキャンは無く最小課金の見込み。FAILED になった
  項目の結果ファイル取得（`aws s3 cp`）・オーファンデータの確認（`aws s3 ls --recursive`）は S3 の読み取りで
  Athena のクエリ課金には乗らない

## 項目 ID の一覧

`<NS>` は `S3TABLES_NS`、`<NOPE>` は `<PROBE>_nope_ns`（無い名前空間）、`<S3>` は
`Catalog=<S3TABLES_CATALOG>,Database=<NS>`、`<S3NOPE>` は `Catalog=<S3TABLES_CATALOG>,Database=<NOPE>`、
`<S3NODB>` は `Catalog=<S3TABLES_CATALOG>` だけ（Database 省略）。

### Database 省略（issue のコメント）。すべて `<S3NODB>`

| ID | SQL の形 | 何を確かめるか |
|---|---|---|
| d0 | `SELECT 1` | 対照。疎通そのもの |
| d1 | `CREATE TABLE <t> (n int)`（CTAS でない） | Database 省略時の非 CTAS の弾かれ方 |
| d2 | `CREATE TABLE <t> AS SELECT 1 AS n`（1 部） | Database 省略時の CTAS の弾かれ方 |
| d3 | `CREATE TABLE <NS>.<t> AS SELECT 1 AS n`（ある名前空間の 2 部） | Database 省略でも 2 部で名前空間を
  指定すれば通るか |
| d4 | `CREATE TABLE <NOPE>.<t> AS SELECT 1 AS n`（無い名前空間の 2 部） | 上と同じ形で名前空間が無い場合 |

## 過去の生データの読み直し（2026-09-27、統括役）

#251 のラウンド 15（`$HOME/athena-unquoted-ddl-measurements/run-20260926-231125`）の t1〜t19 を読み直した。

- 位置付きの理由は 2 件だけ: t1（既定の Context、DB が無い `awsdatacatalog.<無い DB>.<t> AS SELECT * FROM <DB>.<無い表>`）が
  `TABLE_NOT_FOUND: line 6:3: Table 'awsdatacatalog.<DB>.<無い表>' does not exist.`、t3（S3 Tables の Context、同じ形）が
  `SCHEMA_NOT_FOUND: line 6:3: Schema '<S3 Tables の内部名>$schema:<DB>' does not exist.`。どちらも接尾辞付き
- CAST の失敗（t2・t4・t5。DB が無い・ある）は位置の無い `INVALID_CAST_ARGUMENT: Cannot cast 'x' to INT.` + 接尾辞
- 表の参照は受け取った文では 1 行目（`... AS SELECT * FROM ` の後ろ）にあり、`line 6:3` とは行も桁も合わない。組み直しの規則は
  2 件（どちらも SELECT の直後の FROM の表）からは決められない
- `WITH NO DATA` は、DB が無い形（t9）が `Database <db> not found ...`、DB がある形（t10）が SUCCEEDED。問い合わせが失敗する形は無い
- S3 Tables の Context の名前空間が無い CTAS は t16（1 部、Context の Database が無い名前空間）と t17（2 部）だけ。どちらも
  `NOT_FOUND: Schema <内部名>$schema:<名前空間> not found.` + 接尾辞（2 / 1300）。Database を省略した形、IF NOT EXISTS、大文字の名前空間、
  問い合わせの失敗・無い表との順序、データの置き残しは測っていない
