# #294 S3 Tables の Context の CTAS の TABLE_NOT_FOUND の表名を本物の内部名に合わせるかを決める

## 出どころ

- issue #294。#273 の先行実測（ROUND=19、2026-09-27、`tools/measure/unquoted-ddl.sh` の生データ
  `$HOME/athena-unquoted-ddl-measurements/run-20260927-001229` の f7）で見つけた、本物との差が根拠。
  #273 では扱っていない（#273 は書き込む先の名前空間が無いときの `NOT_FOUND` だけを本物の文言にした）。
- 既知の事実（f7、生データそのもの。以下は実名を伏せて書く）:
  S3 Tables の Context（`Catalog=s3tablescatalog/<bucket>,Database=<ns>`）で
  `CREATE TABLE <無い名前空間>.<t> AS SELECT * FROM <ns>.<無い表>` を投げると、本物は開始して
  FAILED（2/1301）になり、理由は
  `TABLE_NOT_FOUND: line 1:98: Table '"awsdatacatalog$iceberg-aws"."catalog:<アカウント ID>:s3tablescatalog/<bucket>$schema:<ns>".<無い表>' does not exist.`
  + CTAS の接尾辞（` You may need to manually clean the data at location '<OutputLocation>' before
  retrying. Athena will not delete data in your account.`）だった（無い表の解析が名前空間より先。
  位置 `line 1:98` は送った文のまま）。
- athena-local は Trino の表名（`iceberg.<ns>.<無い表>' does not exist` のような Trino 側の名前）の
  まま接尾辞を付けて返すので、本物とは表名の形が食い違う。順序（無い表 → 名前空間）と位置は本物と
  同じ。
- 継承できる事実（issue 本文より）:
  - 実測の記録: `docs/dev/measurements/statements.md` の「S3 Tables の Context の名前空間が無い
    CTAS と、Database を省略した Context（#273）」。
  - #273 で `NOT_FOUND` の内部名のアカウント ID を `000000000000` にすると人間が決めた（今回も
    同じ固定値を使えるかは、この実測の結果とアカウント ID の桁が一致するかで決める）。
  - 表の参照の内部名が CTAS 以外（SELECT・INSERT）でも同じか、名前空間があるときも同じかは
    未測定（`docs/dev/unmeasured.md` の #273 の行）。
  - 無い列など、ほかの解析エラーと名前空間の順序も未測定（同上）。
- 推奨する経路（issue 本文より）: 文言の範囲（CTAS 以外の文）を先に測るなら request-measurement、
  そのあと implement-issue。

## 実測の手順

```
cd /home/aoyagikouhei/git/athena-local/.claude/worktrees/measure-294
tools/dev.sh OUTPUT=s3://your-bucket/prefix/ DB=your_db \
  S3TABLES_CATALOG=s3tablescatalog/your-bucket S3TABLES_NS=your_ns \
  bash tools/measure/s3tables-table-not-found.sh
```

- スクリプトのパス: `tools/measure/s3tables-table-not-found.sh`（新規）
- 必須の環境変数: `OUTPUT`（`s3://bucket/prefix/` の形、末尾に `/`）
- 任意の環境変数:
  - `DB`（省略するか実在しなければ `ListDatabases` の一覧の 1 件目を使う）
  - `S3TABLES_CATALOG`（例 `s3tablescatalog/your-bucket`）・`S3TABLES_NS`（`S3TABLES_CATALOG` の
    中の実在する名前空間）。どちらか欠けるか、その Context で `SELECT 1` が通らなければ、S3 Tables
    の項目（t1・t3〜t16）はすべて未測定になり、既定の Context だけの対照（t2）だけを測る
  - `CATALOG`（既定 `AwsDataCatalog`）・`REGION`（既定 `ap-northeast-1`）・
    `OUT_DIR`（既定 `${DEV_HOST_HOME:-$HOME}/athena-s3tables-table-not-found-measurements`）・
    `POLL_TIMEOUT`（既定 180 秒）・`RETRY_MAX`（既定 4）・`RETRY_DELAY`（既定 5 秒）
- 出力先: `${DEV_HOST_HOME:-$HOME}/athena-s3tables-table-not-found-measurements/run-<日時>/`
- 本物への呼び出し回数の見込み（`StartQueryExecution`。`ListDatabases` は Athena のクエリではないので
  含めない）:
  - `S3TABLES_CATALOG`・`S3TABLES_NS` が揃い、その Context の疎通も通るとき: 21〜28 回
    - preflight 2（既定の Context の `SELECT 1`、S3 Tables の Context の `SELECT 1`）
    - 準備 2（`<P>_s3` の `CREATE TABLE` + `INSERT`）
    - 主要項目 16（`t1`〜`t16`）
    - 後始末 1（`<P>_s3` の `DROP TABLE`）
    - `t1`・`t3`〜`t6`・`t14`・`t15`（`CREATE TABLE`、7 項目）が想定に反して受理されたら、その場で
      消す後始末が最大 7 本増える
  - 揃わない・疎通が通らないとき: 2 回（既定の Context の `SELECT 1` + `t2`）
  - このほかに `ListDatabases` を preflight で 1 回、`HeadObject`（結果ファイル本体・`.metadata`
    の有無の確認）を開始できた項目ごとに最大 2 回呼ぶ（どちらも上の回数には含めない）
- DDL・書き込み: S3 Tables の名前空間 `S3TABLES_NS` に表 `<P>_s3`（`CREATE TABLE (n int)` +
  `INSERT` で 1 行）を作り、最後に `DROP TABLE` で消す（trap でも保険をかける）。`t1`・`t3`〜`t6`・
  `t14`・`t15` は CTAS で、無い表・無い名前空間・無い列が対象のため失敗する見込みだが、想定に反して
  受理されたらその場で `DROP TABLE` して消す。
- 課金: `<P>_s3` は 1 行だけ。ほかの項目は無い表・無い名前空間・無い列を対象にしていて解析・実行前に
  落ちる見込みなので、スキャンが乗るとしてもこの小さな表が対象。
- 要る IAM 権限: `athena:StartQueryExecution`・`athena:GetQueryExecution`・`athena:ListDatabases`・
  `s3:GetObject`（`HeadObject` も同じ権限）・`s3:PutObject`・`s3:ListBucket`（`OUTPUT` のバケット）。
  S3 Tables のカタログ・名前空間・表を読み書きする権限（lakeformation・s3tables 側の設定）は、
  `S3TABLES_CATALOG`・`S3TABLES_NS` の疎通確認（S3 Tables の Context の `SELECT 1`）で確かめる。
  それが通らないロールでは S3 Tables の項目は自動的に未測定になる。

## 項目 ID の一覧

準備: S3 Tables の名前空間 `S3TABLES_NS` に実在する表 `<P>_s3`（`CREATE TABLE <P>_s3 (n int)`。
#273 の c1 で S3 Tables の Context で成功すると実測済みの形）を作り、1 行 `INSERT` する。最後に
消す。無い表は `nosuch294`、無い名前空間は `nosuchns294`、無い列は `nosuch_col`（issue 本文どおり
の固定名。実在しない前提なので乱数を混ぜていない）。
`<S3CTX>` = `Catalog=<S3TABLES_CATALOG>,Database=<S3TABLES_NS>`、
`<DEF>` = `Catalog=<CATALOG>,Database=<DB>`。

| ID | Context | 文の形 | 何を確かめるか |
|---|---|---|---|
| t1 | `<S3CTX>` | `CREATE TABLE nosuchns294.<t> AS SELECT * FROM <S3TABLES_NS>.nosuch294` | 対照。f7 の再現 |
| t2 | `<DEF>` | `SELECT * FROM <DB>.nosuch294` | 対照。既定の Context の TABLE_NOT_FOUND（`Table '<DB>.nosuch294' does not exist` の想定）と比べる |
| t3 | `<S3CTX>` | `CREATE TABLE <S3TABLES_NS>.<t> AS SELECT * FROM nosuch294` | CTAS（書き込む先は実在）。無い表を 1 部で書いた形 |
| t4 | `<S3CTX>` | `CREATE TABLE <S3TABLES_NS>.<t> AS SELECT * FROM "<S3TABLES_CATALOG>".<S3TABLES_NS>.nosuch294` | 同上。3 部の修飾 |

| t16 | `<DEF>` | `SELECT * FROM "<S3TABLES_CATALOG>".<S3TABLES_NS>.nosuch294` | 既定の Context から S3 Tables の表を引いても内部名になるか |

各項目で、開始時に弾かれたら `InvalidRequestException` の Message・`AthenaErrorCode` を、開始できたら
最終状態・`StateChangeReason`・`AthenaError`（`ErrorCategory`・`ErrorType`・`Retryable`・
`ErrorMessage`）・`StatementType`・`SubstatementType`・結果ファイル本体と `.metadata` の有無
（`HeadObject`）を記録する。summary には、理由の中の表名の部分（`Table '...'` の中身）を実名だけ
マスクしたうえで、内部名の形（`"awsdatacatalog$iceberg-aws"."catalog:<ACCOUNT_ID>:<S3TABLES_CATALOG>
$schema:<S3TABLES_NS>".<表>` など）がそのまま読める形で 1 項目 1 行で出す。アカウント ID・バケット・
名前空間・DB・接頭辞の乱数は伏せる。

`t1`・`t3`〜`t6`・`t14`・`t15`（`CREATE TABLE`）は、想定に反して受理されたらその場で `DROP TABLE` して
消す。`t2` だけ `S3TABLES_*` の有無にかかわらず測る（既定の Context だけの対照）。それ以外の項目は
`S3TABLES_CATALOG`・`S3TABLES_NS` が揃わない、またはその Context の疎通（`SELECT 1`）が通らなければ
すべて「未測定」として summary に残り、全体は止めない。`t10`・`t13`〜`t15` は `<P>_s3` が作れなければ
個別に「未測定」になる。
