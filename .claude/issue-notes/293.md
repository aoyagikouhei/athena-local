# #293 S3 Tables の Context のバッククォートの名前の CTAS を本物どおり開始時に弾く

## 出どころ

- issue #293。#273 の先行実測（ROUND=19、2026-09-27、生データ
  `$HOME/athena-unquoted-ddl-measurements/run-20260927-001229` の f11）で見つけた本物との差が根拠。
- 既知の事実（f11 の生データ。`f11.context.txt`・`f11.sql`・`f11.start.err`）:
  S3 Tables の Context（`Catalog=s3tablescatalog/<bucket>,Database=<S3TABLES_NS>`）で
  ``CREATE TABLE `<無い名前空間>`.<t> AS SELECT 1 AS n`` を投げると、本物は**開始時に**
  `Creation of tables using select query uses a different syntax. Please see
  https://docs.aws.amazon.com/athena/latest/ug/ctas.html`（`InvalidRequestException`、
  `AthenaErrorCode: MALFORMED_QUERY`）で弾いた。
- 同じラウンドの他の項目との対照（同じ生データの `summary.txt`）: 無引用の 1 部・2 部（f1・f2）、
  `IF NOT EXISTS`（f3）、大文字（f4）、`WITH NO DATA`（f5）、`CAST` 失敗（f6）、存在しない表からの
  SELECT（f7）、`WITH (format='PARQUET')`（f8）、既定の DB を 2 部目に書いた形（f9）、
  `awsdatacatalog.<DB>.<表>` からの SELECT（f10）、二重引用符（f12）はいずれも**開始はできて**
  `NOT_FOUND: Schema catalog:<アカウント ID>:<S3TABLES_CATALOG>$schema:<名前空間> not found. You
  may need to manually clean the data at location '<OutputLocation>tables/<id>' before retrying.
  Athena will not delete data in your account.`（2/1300）で FAILED になった。バッククォート
  （f11）だけが違う挙動になった。
- athena-local には `different syntax` の実装が無い（`src` を grep して確認済み）ので、この差は
  未対応のまま。
- 継承できる事実（issue 本文・#293 の「継承できる事実」より）:
  - 実測の記録: `docs/dev/measurements/statements.md`（現時点では #273 自身がまだ実装・ドキュメント化
    されていないため、#273 用の節はまだ無い。#270 の節の「備考」に f7 の位置についての言及があるだけ）
  - CTAS でない `CREATE TABLE` のバッククォートの表名は #248 の s11 など別の判定
    （`unquoted_ddl::create_table::hive`）。ここでは対照としてだけ測る（別判定に触らない）
  - #273 本体（S3 Tables の Context の 1 部・2 部の CTAS で名前空間が無いときの失敗、
    `NOT_FOUND: Schema ... not found`）はまだ実装されていない（issue #273 は 2026-09-27 時点で
    OPEN）。このスクリプトは #273 の実装を前提にしない（f11 の文言だけを掘り下げる）
  - 推奨する経路: 測っていない形を先に測るなら request-measurement（このラウンド）、測った形だけなら
    quick-implement か implement-issue（#273 との実装の重なりで判断が要る可能性がある）

## 実測の手順

```
cd /home/aoyagikouhei/git/athena-local/.claude/worktrees/measure-293
tools/dev.sh OUTPUT=s3://your-bucket/prefix/ DB=your_db \
  S3TABLES_CATALOG=s3tablescatalog/your-bucket S3TABLES_NS=your_ns \
  bash tools/measure/backtick-ctas.sh
```

- スクリプトのパス: `tools/measure/backtick-ctas.sh`（新規）
- 必須の環境変数: `OUTPUT`（`s3://bucket/prefix/` の形、末尾に `/`）
- 任意の環境変数:
  - `DB`（省略するか実在しなければ `ListDatabases` の一覧の 1 件目を使う）
  - `CATALOG`（既定 `AwsDataCatalog`）・`REGION`（既定 `ap-northeast-1`）・
    `OUT_DIR`（既定 `${DEV_HOST_HOME:-$HOME}/athena-backtick-ctas-measurements`）・
    `POLL_TIMEOUT`（既定 180 秒）・`RETRY_MAX`（既定 4）・`RETRY_DELAY`（既定 5 秒）
  - `S3TABLES_CATALOG`（例 `s3tablescatalog/your-bucket`）・`S3TABLES_NS`（実在する名前空間）。
    どちらか無いか、その Context の `SELECT 1` が通らなければ、S3 Tables を使う項目
    （b1〜b7・b12〜b27）はすべて未測定にし、既定の Context の項目（b8〜b11・b28）だけ測る
- 出力先: `${DEV_HOST_HOME:-$HOME}/athena-backtick-ctas-measurements/run-<日時>/`
- 本物への呼び出し回数の見込み（`StartQueryExecution`。`ListDatabases` は Athena のクエリでは
  ないので含めない）:
  - S3 Tables 無し: 28 回（preflight 1（`<DEF>` の `SELECT 1`）+ 準備 1（`<PROBE>_real`）+
    `b8`〜`b11` 4 + `b28` 1 + 後始末 1）
  - S3 Tables あり: 72 回（preflight 2 + 準備 2（`<PROBE>_real`・`<PROBE>_s3`）+ `b1`〜`b28` 28 +
    後始末 2。受理された `CREATE TABLE` ごとにその場で消す `DROP` が 1 本ずつ増える。最大 +25
    （`b1`〜`b25` のすべてが受理された場合。実際には多くが f11 と同じ理由で開始時に弾かれ、
    後始末が要らない見込み））
  - このほかに Athena のクエリでない `ListDatabases` を preflight で 1 回、`HeadObject`
    （結果ファイル本体・`.metadata` の有無の確認）を開始できた項目ごとに最大 2 回呼ぶ
    （どちらも上の回数には含めない）
- DDL・書き込み: `<S3CTX>` に `<PROBE>_s3`（`CREATE TABLE (n int)`、0 行）、`<DEF>` に
  `<PROBE>_real`（CTAS、1 行）を作って最後に消す。`b1`〜`b25` の `CREATE TABLE` は、受理されたら
  その場で同じ Context に `DROP TABLE IF EXISTS` を投げて消す（trap でも保険をかける）。`b27`
  （`INSERT INTO`）が受理されれば `<PROBE>_s3` に 1 行増えるが、その表ごと最後に消す。
- 課金: どの表も 0〜1 行で、スキャンが乗るとしてもこの小さな表・定数値が対象。開始時に弾かれた
  項目（f11 と同じ挙動なら大半）は課金対象にならない。
- 要る IAM 権限: `athena:StartQueryExecution`・`athena:GetQueryExecution`・`athena:ListDatabases`・
  `glue:GetTable`・`glue:CreateTable`・`glue:DeleteTable`・`glue:GetDatabase`・`glue:GetDatabases`・
  `s3:GetObject`（`HeadObject` も同じ権限）・`s3:PutObject`・`s3:ListBucket`（`OUTPUT` のバケット）。
  `S3TABLES_CATALOG`・`S3TABLES_NS` を使う項目は、S3 Tables のカタログ（`s3tablescatalog/<bucket>`）
  へのアクセス権限も要る（テーブルバケットに対する読み書き・名前空間・テーブルの作成・削除。
  正確な `s3tables:*` の権限一覧はこのスクリプトでは実測していない。既存の S3 Tables 対応の
  実測スクリプト（`tools/measure/unquoted-ddl.sh` の S3TABLES_* 系項目）と同じ前提を使う）。
  データカタログ管理 API（`athena:CreateDataCatalog` など）は呼ばない。

## 項目 ID の一覧

準備: `<S3CTX>` に `<PROBE>_s3`（`CREATE TABLE <PROBE>_s3 (n int)`。S3 Tables の Context では
Database が名前空間になるので 1 部の名前で作れる）、`<DEF>` に `<PROBE>_real`
（`CREATE TABLE <DB>.<PROBE>_real AS SELECT 1 AS n`）。存在しない名前空間・DB はいずれも乱数入りの
接頭辞を付けた `nosuchns293`（S3 Tables の名前空間用）・`nosuchns293db`（既定の DB 用）。
`<S3CTX>` = `Catalog=<S3TABLES_CATALOG>,Database=<S3TABLES_NS>`、
`<DEF>` = `Catalog=AwsDataCatalog,Database=<DB>`。

| ID | 文の形（Context） | 何を確かめるか |
|---|---|---|
| b1 | `` CREATE TABLE `<無い名前空間>`.<t> AS SELECT 1 AS n ``（`<S3CTX>`） | 対照。f11 の再現 |
| b2 | `CREATE TABLE <S3TABLES_NS>.<t> AS SELECT 1 AS n`（`<S3CTX>`） | 対照。バッククォート無し（成功見込み） |
| b3 | `` CREATE TABLE `<S3TABLES_NS>`.<t> AS SELECT 1 AS n ``（`<S3CTX>`） | 実在する名前空間をバッククォートで書いた CTAS。f11 と同じ文言になるか（＝バッククォート自体が引き金か、名前空間が無いことも要るか） |
| b4 | `` CREATE TABLE <S3TABLES_NS>.`<t>` AS SELECT 1 AS n ``（`<S3CTX>`） | 表名だけバッククォート |

各項目で、開始時に弾かれたら `InvalidRequestException` の `Message`・`AthenaErrorCode` を、開始できたら
最終状態・`StateChangeReason`・`AthenaError`（`ErrorCategory`・`ErrorType`・`Retryable`・
`ErrorMessage`）・`StatementType`・`SubstatementType`・`GetQueryExecution` の `Query`（送ったままか）・
結果ファイル本体と `.metadata` の有無を記録する（`summary.tsv`・`summary.txt` の列）。
