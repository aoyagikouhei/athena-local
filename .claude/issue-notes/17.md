### 判定ロジックの現状

- `src/operation.rs:638-644` `words()`: `split_whitespace()` した**全トークン**に `trim_start_matches('(')` を掛けて大文字化する。
  doc コメントに「先頭のコメントは考慮しない」と明記（638 行）。
- `words()` の呼び出し元は **3 箇所**（すべて `src/operation.rs` 内、private）:
  - `:353` `metadata_query_id` — `.metadata` の先頭に入れるクエリ ID を Trino の ID にするか `QueryExecutionId` にするかを決める
  - `:648` `statement_type`
  - `:660` `substatement_type`（`is_create_table_as(&words)` にもこの配列を渡す。`:685`）
- `src/results.rs:38-59` `ResultFile::of()`: 括弧を残した配列を作り、`word(0)` を使う瞬間にだけ `trim_start_matches('(')` を掛ける（`:47`）。
  唯一の呼び出し元は `src/operation.rs:219`（`result_location`）。
- **重要な非対称**: `is_create_table_as`（`src/results.rs:86-102`）には 2 種類の形の配列が渡る
  （`operation.rs:685` は括弧除去済み、`results.rs:55-56` は括弧付き）。`:96-101` の
  `starts_with("SELECT") || starts_with("WITH") || starts_with('(')` の 3 通り OR がこの差異を吸収している。**崩さないこと。**
  - 例 `CREATE TABLE t AS (SELECT 1)`: `operation.rs` 側 `[...,"AS","SELECT","1)"]`／`results.rs` 側 `[...,"AS","(SELECT","1)"]`
- レスポンスへの流れ: `statement_type`/`substatement_type` → `to_query_execution`（`:575-576`）→ `get_query_execution`（`:405-407`）→
  `GetQueryExecutionResponse.QueryExecution.StatementType`/`.SubstatementType`。`update_count`（`:629-636`）→ `get_query_results`（`:526`）→
  `GetQueryResultsResponse.UpdateCount`。`ResultFile::of` → `ResultLocation::new`（`results.rs:120-130`）→ `uri()`（`:152-155`）→
  `ResultConfiguration.OutputLocation`。加えて `write_result`（`operation.rs:276-277`）の「本体を書くか」の判断にも効く。
- **先頭のキーワードを見ている箇所は上記 6 関数に閉じている**（grep 済み）。`src/metadata.rs`・`src/convert.rs`・`src/statement.rs` には無い。

### 共有できる字句処理（`src/catalog.rs`）

- `pub` は `alias_qualified_names` だけ。`skip_quoted`(:55) / `comment_end`(:72) / `next_is_dot`(:89) / `unquote`(:103) / `replacement`(:113) は private。
- `comment_end`(:72-86) の挙動: `--` は `\n` の**直前**まで（`\n` 自体は含まない）。`/**/`→4、`/* */`→5、`/*`（未閉じ）→2、`/*/` 単独→3（未閉じ扱い）。
  `rest[2..]` から `*/` を探すので `/*` の `*` を閉じの一部として誤読しない（`catalog.rs:203-204` がテスト済み）。
  ネストしたブロックコメントは内側の最初の `*/` で閉じる（SQL 標準どおりで変える必要なし）。
- `next_is_dot`(:89-100) の「空白とコメントを交互に読み飛ばす」ループがそのまま転用できる。戻り値を `bool` → 位置に変えて切り出せる。
- `src/lib.rs:5` は `mod catalog;`（非 pub）のままでよく、`pub(crate) fn` にすれば `operation.rs`/`results.rs` から `crate::catalog::...` で呼べる。
- 先頭に文字列リテラルが来る有効な SQL 文は無いので、先頭コメント飛ばしで `skip_quoted` は要らない。
