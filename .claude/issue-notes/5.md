### `.txt.metadata` の復号（2026-09-17、#1 の生データ `$HOME/athena-txt-measurements` から）

1. **素の protobuf**：DESCRIBE（152B）、EXPLAIN（79B）、SHOW CREATE TABLE（88B）、DROP TABLE（41B）。`GetQueryResults` が `UpdateCount` を返さない文と一致する。

   - field 4（message、repeated）: 列ごとに 1 つ。`ColumnInfo` と一対一。

### `write_result` の組み替え（フェーズ 3）

```
if results が無いか location が無い → return Ok
if cancel.is_requested() → return Ok（今までどおり何も置かない）
if should_write（Text、または Csv かつ update_count 無し）:
    match put(本体):
        Ok → 続行
        Err かつ Text → eprintln!、return Ok（`.metadata` は試みない）
        Err → return Err(result_write)
if !outcome.columns.is_empty():
    put(location.metadata(), to_metadata(...)) → Err なら eprintln! して握りつぶす
return Ok(outcome)
```

- 本体を書かない文（UPDATE / DELETE / MERGE / INSERT / CTAS）は `.metadata` だけを書く（実測 B / C）。
- 本体を書いた場合は、その PUT が `Ok` のときだけ `.metadata` を書く（`tests/results.rs:312` の PUT 1 回を保つ）。**`.txt` の失敗を握りつぶす腕からも return する**（ここを `match` の後ろに流すと `.txt` が落ちたのに `.metadata` を置く）。
- 列が空なら書かない（CREATE TABLE / CREATE DATABASE / DROP DATABASE の実測と一致。DROP TABLE は本物と食い違う）。
- 取り消しの再確認は入れない（本体 PUT 中の取り消しは既に本体で起きている競合で、`.metadata` が 1 個増えるだけ）。
- `write_result` は 50 行以内。`.metadata` の組み立てと PUT は `write_metadata`（20 行以内）に切る。

### 直列化境界

protobuf の length-delimited の長さは UTF-8 のバイト長（`len()`）。128 バイト以上で varint が 2 バイトになり、列メッセージ全体の長さも連動する。Precision 2147483647 / 1073741824 は 5 バイトの varint（型網羅 710B の実測で固定される）。ライブラリに置き換えない（依存が無く、prost では Scale 0 の明示 `40 00` を出せない）。厄介な入力のテストは 2 件: 非 ASCII の列名 `日本語`（9 バイト。`chars().count()` を殺す）、130 バイトの列名（長さ varint の 2 バイト化と、列メッセージ全体の長さの連動を殺す）。

名前: 「付随ファイル / companion file」（README:331 の語に合わせる）。「エンジン ID」= Trino のクエリ ID、識別子は `engine_query_id` と `execution_id` で分ける。`metadata` は `ResultSetMetadata` と紛らわしいので、モジュール冒頭で「結果ファイルの隣に置く `.metadata` のこと」と断る。

## 計画レビューの結果（Step 6、2026-09-17、Explore 3 本: 契約・呼び出し元 / 再利用・構造 / 削減）

**採用**
- **high**: 計画の「`put` の `Ok` 腕から `write_metadata` を呼ぶ」は、本体を書かない DML が早期 return するため `.metadata` が一切書けない矛盾（3 本とも指摘）。`write_result` を「取り消し → 本体（should_write のときだけ）→ `.metadata`（列があれば）」の順に組み替え、`.txt` の失敗を握りつぶす腕からも return する。`ResultLocation::metadata()` は `file` も `Metadata` に差し替える（`put` は `location.file.content_type()` を使うため）。
- **medium**: 「本体の失敗で `.metadata` を試みない」を SELECT で固定しても `Err` で return するので意味が無い。SHOW TABLES + 500 に変える。
- **medium**: `.metadata` の field 3 に `operation::update_count` を使うと SELECT で `Some(0)` に化ける。一致台帳に行を足す。
- **medium**: 更新件数 0 の DML の field 3 は未実測。`Some(0)` なら書き、未検証の前提と人間検証リストに載せる。
- **削減（採用）**: `s3_status_for` は不要（UPDATE + 全体 500 で `.metadata` だけが失敗する）。`pub(crate) fn words` の切り出しは不要で、`operation.rs` に同名の `words` が既にあり `(` の扱いが違う（ID の出どころは `operation.rs` で決め、`metadata.rs` は文字列を受けるだけ）。`nullable_code` は定数 3 に。`absorb` の「先勝ち」分岐とテストは不要。偽 Trino の `statement` ハンドラで `id` の既定値を入れ、結合テストが本番と同じエンジン ID 経路を通るようにする（フォールバックは式 1 つ、専用テスト無し）。厄介な入力のテストを 6 → 2 件、実機検証を 14 → 9 件、ミューテーションを 12 → 8 件、前提表をテストが固定していない行だけに。README の差分から `SELECT 1` の特別扱いを外す。`tests/results.rs:91` は変更なし。
- **low**: 期待値のバイト列は 710B / 152B / 75B / 60B の 4 本で足りる（EXPLAIN 79B と SHOW CREATE TABLE 88B は重複）。型の表は `ColumnInfo.type_name`（Athena の型名。real は `float`）で引く。CTAS の `tables/` は自分の実測（Iceberg は無し）と食い違うので、テストのコメントと README に「Hive の実測。Iceberg は別 issue」と書く。

**棄却**
- `ColumnInfo` の Precision / Scale を `Option` にして有無を持たせる案（構造の観点の代案）: `GetQueryResults` の JSON から `Precision` が消え、本物（常に出す）と食い違う。`metadata.rs` の 10 行の match の方が 1 画面で読める。
- `.metadata` の前に取り消しを再確認する分岐: 本体 PUT 中の取り消しは既に起きている競合で、新しい壊れ方は生まれない（単純さゲート）。
- 「Trino の `id` が 2 ページ目以降にだけある経路」への備え: `follow` を読んで無いことを確認済み（契約の観点）。

**再レビュー（構造の観点 1 本、書き直した箇所だけ）で採用**: `write_result` に実行 ID を引数で渡すことをファイル構成に明記（`Execution` に `id` は無い）。`update_type` は `clone()` で写す（`take()` すると DML の data が行になる）。`ResultFile::path` に `Metadata` の値を発明しない。`to_metadata` は 4 引数のまま（`&Outcome` にすると `metadata.rs` が `trino` と `convert` に依存し、ユニットテストが `typeSignature` の組み立てを強いられる）。列が空の判定は `write_result` 側。

**指摘にならなかった点**: `Retention` / `sweep` は S3 を触らない。`EXECUTE IMMEDIATE` で包んでも `updateType` / `id` / 列は変わらず、`write_result` が見る `execution.query` は受け取ったままの SQL。`ResultFile::path` / `content_type` に腕を足しても `-D warnings` は通る。
