- 2026-09-16 **判断 4（実 AWS 発信への対応）: README に明記するだけ。コードは変えない。** 計画レビューが見つけた「`GetWorkGroup` の実装が awswrangler の実 AWS 発信の防波堤を外す」件（下の「採用 3」）への対応。`ManagedQueryResultsConfiguration.Enabled = true` で防ぐ案は採らない。理由: (a) 本物の Athena に合わせるという CLAUDE.md の目的から外れる (b) 守れるのは `ctas_approach=False` の経路だけで `unload_approach=True` は守れない (c) `AWS_ENDPOINT_URL` を全サービスに効く形で設定していれば実 AWS には出ない (d) awswrangler 自身も `UserWarning` を出す。**この判断により `ManagedQueryResultsConfiguration` は型ごと定義しない。**（実測でも本物に存在しなかったので、結果として本物と一致した）
- 2026-09-17 **判断 5（`ResultConfiguration` の形）: 本物に合わせて常に返す。** 実測で、本物は出力先が設定されていなくても `Configuration.ResultConfiguration` をキーとして持ち、中身が空のオブジェクト `{}` になることが分かった。計画の「出力先が無ければ `ResultConfiguration` ごと省く」を取り下げる。出力先があれば `{"OutputLocation": ...}`、無ければ `{}` を返す。既存の `ResultConfiguration` 型（`output_location: Option<String>` に `skip_serializing_if`）をそのまま使い、`WorkGroupConfiguration` 側で `Option` にしなければこの形になる。**新しい型も分岐も増えない。**

## 計画（Step 5、Step 6 のレビューを反映した確定版）

### GetWorkGroup の契約

`WorkGroup.Name` はリクエストの `WorkGroup` をそのまま返す。`State`／`Configuration` はリクエストに依存せず、`Config`（環境変数）と実測した固定値だけから決まる。**名前が違っても `Configuration` は同じ。**

### フェーズ分割: 1 フェーズ

本番コード 150 行ほどの規模で、分ける理由が無い。`Store::submit` の構造変更を別フェーズにする案は、レビューの削減の観点どおり取り下げた（増えるのはコミットと検証の回数だけでリスクは減らない）。`Submission` への変更と `GetWorkGroup` の追加を 1 コミットにまとめる。

### 型に入れないもの

- **`CreationTime`**（Step 6 採用）。実測で本物は返しており、ワイヤ上は `f64` の epoch 秒だと分かった。**それでも返さない。** 理由は「未実測だから」ではなく、**athena-local にワークグループの作成時刻という実体が無いから**。起動時刻でも毎回の `now()` でも、本物らしく見える偽の値を作ることになる。botocore の必須は `Name` だけで、3 クライアントとも読まない（ソース全文を grep してヒット 0 件）。CLAUDE.md 59 行目の「項目を省く」に従う。**本物との差分として README に書く。**
- **`ManagedQueryResultsConfiguration`**（判断 4）。実測でも本物に存在しなかったので、省くことが本物と一致する。
- **`Description`**。実測でも本物に無かった（2 つのワークグループとも）。省くことが本物と一致する。
- **`EnableMinimumEncryptionConfiguration`**。実測で `Configuration` 直下にキーの存在は確認できたが、**値が採れていない**。CLAUDE.md 59 行目の「実測していない振る舞いは推測で埋めない。項目を省く」に従って省く。README の Caveats に「未実測」と書く。

### この計画で決める細部

- **`WorkGroup` が未指定のとき**: `GetWorkGroupRequest.work_group: String` を必須フィールドにすれば、既存の `parse()`（`src/response.rs:56-59`）が自動で `InvalidRequestException` にする。特別なコードは足さない。
- **空文字**: 特別扱いしない。そのまま `Name` に返す。テストは置かない（botocore の `WorkGroupName` は `[a-zA-Z0-9._-]{1,128}` なので実クライアントからは届かない）。
- **直列化・正規化境界**: 該当なし。SQL を組み立てず、Trino にも Store にも問い合わせず、文字列連結も突き合わせも無い。

### ミューテーション確認で壊す候補

- `WorkGroup.Name` をリクエスト値でなく `"primary"` 固定に戻す（判断 2 を壊す）。
- `Configuration.ResultConfiguration` を常に `None`／常に `Some` にする。
- `EnforceWorkGroupConfiguration` を `Option` + `skip_serializing_if` にする（必須項目が消える）。
- `EffectiveEngineVersion` を別の値にする。
- `DEFAULT_WORK_GROUP` を変える、または既定を当てる処理を外す。
- `to_query_execution` の `work_group` を定数に戻す。
- `get_work_group` の中で `app.trino` を呼ぶ（`trino_には一切問い合わせない` で**検知できる**）。
- `get_work_group` の中で `app.store` を呼ぶ（**検知できない。** `Store` はテストダブルではなく本物が使われ、呼ばれたかを外から観測する手段が無い。実装時に目で確認する。Store を計測する足場は足さない）。
