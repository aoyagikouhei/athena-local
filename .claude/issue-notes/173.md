### 本物の行の形（B。すべて real の run。生データのパスは Explore B の返答どおり）
10. **DESCRIBE（Hive）**: ColumnInfo は `col_name`/`data_type`/`comment` の 3 列（string、Precision 0、CaseSensitive false）。各行の `Data` は 1 個。値は `<列名を 20 桁に左詰め>\t<型を 20 桁に左詰め>\t<コメント>`。20 桁ちょうどは詰めない（`pattern_history_uuid`）。コメントが空なら空白 20 個、空でなければ詰めない（`a`。タブ以降は消える）。末尾にタブ無し。パーティション付きは通常列の後に `\t \t `、`# Partition Information\t \t `、`# col_name            \tdata_type           \tcomment             `（`# col_name` + 空白 12 = 22 桁）、`\t \t `、続けてパーティション列（同じ形）。パーティション無しなら見出し行群は無い。出てきた型は `char(36)`・`timestamp`・`string`・`int` の 4 つだけ。UpdateCount null。
11. **DESCRIBE（Iceberg、u1）**: ColumnInfo は Hive と同じ 3 列。6 行、詰め無し: `# Table schema:\t\t`、`# col_name\tdata_type\tcomment`、`n\tint\t`、`\t\t`、`# Partition spec:\t\t`、`# field_name\tfield_transform\tcolumn_name`。パーティション無しでも `# Partition spec:` の見出しが出る。区切りは `\t\t`（Hive は `\t \t `）。UpdateCount 0、binary、`.metadata` 568B 不透明。
12. **`.txt`**: GetQueryResults の値を `\n` で連結したものと 1 対 1 で同じ（空白・タブも）。末尾改行なし。Hive の DESCRIBE は application、`.metadata` 152B の素の protobuf。
13. **SHOW COLUMNS**: ColumnInfo は `field` 1 列（string）。Hive は列名を 20 桁に左詰め（20 桁ちょうどは詰めない）、Iceberg は詰めない（`n`）。パーティション列も含む（DESCRIBE の上半分と同じ行数）。UpdateCount 0、binary、`.metadata` 312B 不透明。`SHOW COLUMNS FROM /* c */ t` も SUCCEEDED。
14. **SHOW TABLES**: `tab_name`/string、行は素の名前。0 件なら 0 行・0B。**SHOW DATABASES**: `database_name`/string、素の名前。`SHOW DATABASES LIKE '<無し>'` は ColumnInfo 付きの 0 行・UpdateCount 0。**SHOW SCHEMAS を本物に投げた run は無い。**
15. SHOW VIEWS `views`/**varchar**（0 行の例だけ）、SHOW PARTITIONS `partition`/string（素の `k=v/k=v`）、SHOW TBLPROPERTIES `prpt_name`・`prpt_value` の 2 列で Data 1 個（`キー\t値`、値の改行で行が割れる）。athena-local には届かない（Trino が弾く）。
16. `QueryPlanningTimeInMillis` は SHOW・DESCRIBE のすべてで無い。SubstatementType は `DESCRIBE_TABLE`・`SHOW_COLUMNS`・`SHOW_TABLES`・`SHOW_DATABASES`。
17. 未実測（B の列挙）: 20 桁を超える列名・型、`bigint`・`decimal`・`array<>`・`struct<>`・`varchar(n)`・`double` などの `data_type` の表記、20 桁を超えるコメント、Iceberg のパーティション付き／コメント付きの DESCRIBE と SHOW COLUMNS、`SHOW SCHEMAS`、`SHOW TABLES LIKE`、ビューへの DESCRIBE。

### 手元の Trino 482 で確かめたこと（統括役、2026-09-24 20:36。compose の trino に `docker exec … trino --execute`）
24. Hive connector の `DESCRIBE`／`SHOW COLUMNS` はどちらも `Column`／`Type`／`Extra`／`Comment` の 4 列で、パーティション列は `Extra` が `partition key`、コメントは `Comment` に入る。型は Trino の綴り（`integer`、`varchar`、`decimal(10,2)`、`timestamp(3)`、`array(varchar)`、`row("x" integer, "y" varchar)`）。Iceberg connector は同じ 4 列だが、パーティション列（`partitioning = ARRAY['p', 'month(ts)']`）でも `Extra` は空で、パーティションの情報は DESCRIBE からは取れない。`SHOW TABLES` は `Table` 1 列、`SHOW SCHEMAS` は `Schema` 1 列。

### 未検証の前提の裏取り（Explore、2026-09-24 20:49。Trino 482、作ったものは DROP 済み）
25. Hive connector はパーティション列を最後に置くことを CREATE TABLE で強制する（`Partition keys must be the last columns in the table and in the same order as the table properties`）。`ADD COLUMN` の後もパーティション列は最後。Iceberg は途中の列でも受け、DESCRIBE は書いた順で `Extra` は空。
26. コメントの無い列の `Comment`・`Extra` は Hive／Iceberg とも空文字（null ではない）。タブ・改行入りのコメント（`COMMENT ON COLUMN`）は Trino がそのまま返す（`a\tb`、`x\ny`）。
27. Hive の DESCRIBE の `Type` の綴り: `integer`, `varchar`, `timestamp(3)`, `char(36)`, `bigint`, `double`, `real`, `boolean`, `date`, `decimal(10,2)`, `varchar(10)`, `varbinary`, `tinyint`, `smallint`, `array(varchar)`, `map(varchar, integer)`, `row("a" integer, "b" varchar)`（row のフィールド名は二重引用符付き）。**Iceberg は `timestamp`→`timestamp(6)`、`char(36)`→`varchar`、`varchar(10)`→`varchar`、`tinyint`／`smallint`→`integer` に丸まる**（Trino の Iceberg 型）。ほかは Hive と同じ。
28. `DESCRIBE OUTPUT x`／`DESCRIBE INPUT x` は PREPARE 無しでは Trino が `Prepared statement not found`（NOT_FOUND）で失敗し、作り直しには届かない。athena-local の分類は `word(0) == "DESCRIBE"` だけで `DESCRIBE_TABLE`。
29. `SHOW COLUMNS FROM t` の列名の並びは DESCRIBE と同じ `Column`／`Type`／`Extra`／`Comment`（Hive・Iceberg とも。JSON で確認）。
